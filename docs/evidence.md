# tuzi — 근거: 반복 요청에서 뽑은 스킬

> 836개 세션 전사(1.2G, 2026-07-22 ~ 2026-10-05)에서 **사람이 직접 쓴 메시지
> 1,362건**을 걸러 빈도를 세고, 그 위에 메모리 8건·`~/.claude/CLAUDE.md`·
> `HANDOFF.md` 를 얹어 만들었다.
>
> v1(`tuzi-core`)은 반복 지시 하나당 스킬 하나, **10개**였다. v2 는 같은 규칙을
> 소프트웨어 라이프사이클 단계로 다시 묶었다 — 이름이 규칙을 따라 지어져 무엇을
> 불러야 할지 떠올리기 어려웠다. 매핑은 2장.

## 0. 왜 이 묶음인가

같은 지시를 여러 세션에서 반복해 입력했다는 것은, **그 지시가 기본 동작이 아니라는
뜻**이다. 반복 횟수가 곧 "기본값이 틀어져 있는 지점"의 측정값이다. 그래서 스킬의
단위를 기능이 아니라 **반복된 지시**로 잡았다.

**빈도만으로 정하지 않는다.** 가장 중요한 축 하나는 건수가 2.2% 밖에 안 됐다
(§1.4 참조). 지시가 **질문형·추궁형으로 반복**되면 건수가 작아도 신호는 더 세다.

앞선다. 반복 요청의 무게는 *무엇을 만드느냐* 가 아니라 **만든 것이 진짜 되는지,
그것을 어떻게 전하느냐**에 쏠려 있다.

### 1.4 빈도가 낮아도 스킬로 올린 것 — 그리고 처음에 놓친 것

**1차 집계는 오케스트레이션 축을 통째로 빠뜨렸다.** 주제 집합에 그 항목이 없었기
때문이다. 사용자가 *"에이전트 또는 오케스트레이션 모드 구성 같은 요청도 있었잖아?"*
라고 지적해 다시 셌고, 30건(2.2%)이 나왔다. **키워드 집계는 넣은 주제만 찾는다** —
빈도가 0 인 것과 주제가 없는 것은 출력에서 구별되지 않는다.

건수가 작아도 올린 것들의 공통점은, **지시가 추궁의 형태로 반복됐다**는 것이다.

| 축 | 건수 | 어떤 형태로 반복됐나 |
| --- | --- | --- |
| 오케스트레이션 구성 | 15 | *"구성해 달라고 했는데 구성이 필요 없어서 안한거야?"* — 요청을 판단으로 건너뛴 것에 대한 추궁 |
| 워커 위임·상태 | 15 | *"오케스트레이션 모드로 도는게 아니라 니가 다 하고 있잖아"* — 두 번 나왔다 |
| 근본 원인 | 9 | `근본 원인 해결해줘.` 가 **그대로** 4회 |
| 과잉 금지·토큰 | 5 | 매번 표현이 달라 키워드가 놓친다. 메모리에 사고 기록으로 남아 있다 |
| 자율 수행 | 1 | 이번 세션에 명시 지시로 나왔다. 집계에는 1건뿐이다 |

반대로 **1회성 지시는 스킬로 만들지 않았다.**

### 단계 사이의 관계

```
start ──▶ go ⇄ fix ──▶ check ──▶ report ──▶ ship ──▶ handoff ──▶ (다음 세션) go
          └──────────── auto 가 이 구간을 멈추지 않고 돈다 ────────────┘

team = 위 흐름을 여러 워커로 나눠 돌릴 때 (plan → setup → run → status)
```

## 3. 다른 세션에서 취합하는 방법

```bash
python3 tools/harvest.py ~/.claude/projects                # 기본 (2회 이상)
python3 tools/harvest.py /경로/projects --min-count 3       # 임계 조정
python3 tools/harvest.py /경로/projects --short-len 60      # 더 긴 지시까지 "짧은 지시"로
```

출력은 셋이다 — ① 반복된 짧은 지시 ② 주제별 빈도 ③ 주제별 표본. 전부 마크다운이라
그대로 이 README 에 붙일 수 있다.

### 이 스크립트가 두 번 틀렸던 지점

**① 주입 턴.** 전사의 `type: "user"` 에는 오케스트레이터 프리앰블·검증 에이전트
디스패치·슬래시 커맨드가 섞여 있다. 걸러내지 않으면 `# 규칙 ## CONV-001` 같은 기계
문장이 상위를 다 차지한다 — 1차 집계에서 **`보고-전후대조 357건` 이 나왔는데 전부
주입이었다.** → `INJECTED` 필터

**② 제품 도메인 어휘.** `moai-agent`·`mark agent` 같은 **제품의** 에이전트와
이미지 붙여넣기 경로(`orca-paste-…`)가 오케스트레이션 축을 81건으로 부풀렸다.
표본을 열어 보니 전부 이미지 경로였다. → `NOISE` 필터 + `PRODUCT_AGENT`

**교훈** — 숫자를 받으면 **표본을 반드시 열어 본다.** 두 번 다 숫자만 보면 통과했고,
표본을 열어 본 순간 드러났다.

### 취합 절차

1. 각 세션/기계에서 `tools/harvest.py` 를 돌려 ①②③을 받는다
2. **③ 표본을 먼저 읽는다.** 숫자가 그럴듯해도 표본이 노이즈면 ②는 무효다
3. 새로 **2회 이상 반복된 지시**가 나오면, 기존 라이프사이클 명령 중 어디에 속하는지 본다
4. 어디에도 안 붙으면 그 지시가 **어느 라이프사이클 단계에서 나왔는지** 본다. 단계가 있으면
   그 스킬에 절을 늘리고, 단계 자체가 없으면 명령을 하나 늘린다. 억지로 붙이면 스킬이 뭉개진다
5. 붙으면 그 스킬의 「왜 이 단계가 있나」 절에 횟수와 발화를 **추가**한다.
   규칙 본문은 손대지 않는다
6. 기존 규칙과 **모순**되는 지시가 나오면 그게 가장 중요한 신호다 — 규칙이 틀렸거나
   맥락이 둘로 갈린 것이다. 둘 다 적고 조건을 붙인다
7. **`THEMES` 에 없는 축은 0건으로 나오지 않고 아예 안 나온다.** 표본 ③에서 어디에도
   안 걸린 지시가 보이면 주제를 늘린다
8. 집계를 갱신했으면 이 문서의 숫자도 같이 고친다. 문서와 스크립트가 어긋나면
   다음 사람이 문서를 믿는다

## 4. 설치

저장소 루트 [README](../README.md) 를 본다.

### CLAUDE.md 와 겹치는 것 — 빼지 않는다

| 스킬 | `~/.claude/CLAUDE.md` 에서 겹치는 절 | 어떻게 두나 |
| --- | --- | --- |
| `report` | 「변경 보고 규약」 | **CLAUDE.md 에 둔다.** 코드를 고친 뒤의 보고는 사실상 매 턴이다. `/report` 를 부르지 않은 보고에도 걸려야 한다 |
| `report` | 「산출물 폰트 규약 (Pretendard)」 | 둬도 된다. 문서 파일을 만들 때만 쓰여 `report` 만으로도 덮인다 |

처음에는 "설치하면 둘 다 뺀다" 로 적었다. 그러나 그러면 아래 원칙과 부딪힌다 —
「응답 언어」·「응답 어조」 절을 스킬로 옮기지 않은 이유가 **모든 턴에 적용**되는
것이라서였고, 변경 보고도 같은 성격이다. 스킬은 호출돼야 읽힌다. 겹침의 비용(한쪽만
고치는 것)은 CLAUDE.md 쪽을 **짧은 요약**으로, `report` 쪽을 **상세판**으로 역할을
나눠 줄인다.

## 5. 이 묶음이 덮지 못하는 것

- **프로젝트 고유 지식** — 게이트 스크립트 이름, 바꾸면 안 되는 암호화 키, 착수 전부터
  빨간 드리프트 검사. 이건 스킬이 아니라 그 저장소의 `CLAUDE.md`·`HANDOFF.md` 자리다
- **도구 의존 규칙** — 2026-10-05 에 hi-loop·code-viz·bkit 을 지웠다. 도구 이름이
  박힌 규칙은 도구가 사라지면 거짓말이 된다. **이 묶음의 스킬은 도구를 지명하지 않는다.**
  `team` 도 "그 환경의 도구 문서를 먼저 읽는다" 로 썼다
- **모든 턴에 적용되는 것** — 언어·어조
- **1회성 지시** — 반복되지 않은 것은 스킬이 아니다
