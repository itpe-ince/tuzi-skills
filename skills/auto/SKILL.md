# 끝까지 돈다

입력: `$ARGUMENTS` (목표. 비었으면 `/tuzi:go` 의 복원 절차로 목표를 찾는다)

## 왜 이 명령이 있나

`끝나면 알려줘`(4회), `qa 끝나면 갭 수정까지 바로 진행해`(3회) 가 반복됐다.
단계 하나를 끝낼 때마다 멈춰서 다음을 물었기 때문이다. **단계 경계는 멈출 자리가
아니다.** 이 명령은 각 단계 스킬을 순서대로 이어 붙인 것이다 — 규칙은 각 스킬에 있다.

## 흐름

```
 ┌─▶ 1. go     한 수를 정해 구현 (버그면 fix 규칙)
 │   2. check  실물 확인 1라운드 ─── 갭 발견 ──┐
 │   3. report 3열 대조 + 확인/미확인          │
 │   4. ship   게이트 → 로컬 커밋              │
 │   5. 목표 남았나? ── 예 ─────────────────────┘
 └──────────── (갭·남은 목표가 있으면 1로)
     6. 끝 — 알린다 (컨텍스트 70% 면 handoff 후 알린다)
```

각 단계에서 **해당 스킬의 규칙을 그대로 따른다**: `/tuzi:go` · `/tuzi:fix` ·
`/tuzi:check` · `/tuzi:report` · `/tuzi:ship` · `/tuzi:handoff`.

## 멈추는 곳 — 이 셋뿐이다

| 멈춤 | 어떻게 |
| --- | --- |
| 워크트리 밖 작업 (push·운영 DB·외부 전송·전역 설정) | 안의 일을 **다 끝낸 뒤** 모아서 한 번 묻는다 |
| 결과가 실질적으로 갈리는 선택 | 권고 하나 + 사유 한 줄로 묻고, 답과 무관한 일은 계속한다 |
| 같은 실패가 **3회** 반복 | 멈추고 원인 가설과 시도한 것을 보고한다. 네 번째로 같은 걸 하지 않는다 |

그 외에는 묻지 않는다. 단계 사이에 "다음 진행할까요?" 를 넣지 않는다.

## 상한

- 검증은 단위마다 **1라운드**. 보안·데이터 손실만 차단, 나머지는 기록 (`/tuzi:check`)
- 커밋은 **작업 단위마다** 로컬로. push 는 하지 않는다 (`$ARGUMENTS` 에 명시돼 있으면 마지막에 1회)
- 컨텍스트 **70%** 에 닿으면 새 단위를 시작하지 않고 `/tuzi:handoff` 후 알린다
- 사용자가 "그만"·"빨리" 라고 하면 현재 단위만 마무리하고 끝낸다

## 끝 보고

```
## 끝났습니다 — <목표 한 줄>

| 커밋 | 무엇 | 확인 |
| abc1234 | … | e2e 1회 성공, tests/screenshots/x.png |
| def5678 | … | 단위 테스트만 — 실물 미확인 |

## 확인하지 않은 것
- …

## 기다리는 것 (워크트리 밖)
- origin push — 말씀하시면 `/tuzi:ship push`
```

중간에 멈췄으면 제목을 **"멈췄습니다 — <어디서, 왜>"** 로 쓴다. 끝난 것처럼 쓰지 않는다.
