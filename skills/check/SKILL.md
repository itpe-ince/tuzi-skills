# 3. 돌려 보지 않은 것을 됐다고 적지 않는다

입력: `$ARGUMENTS` (비었으면 `git status` 의 미커밋 변경이 대상)

## 왜 이 단계가 있나

`확인` 이 사람이 쓴 메시지의 **11.0%(150건)** 로 지시 동사 중 1위다. `띄워` 40건,
`스크린샷`·`캡처` 13건이 뒤를 받친다. `다시 확인해봐` 가 반복됐다 — **이미 한 보고를
사용자가 믿지 못했다는 기록이다.** `구현`(1.2%)보다 아홉 배 많다.

반대 방향의 실패도 있다. 커밋 하나에 검증을 **5라운드** 돌았고, 4·5라운드가 찾은 것은
*"테스트가 테스트를 제대로 검사하는지"* 였다. 그 2주 동안 제품은 한 번도 돌지 않았다.
**덜 확인하는 것도, 엉뚱한 층을 더 확인하는 것도 같은 실패다.**

## 완료 기준

> **완료는 끝에서 끝까지 1회 성공이다. 단위 테스트가 아니다.**
> **그리고 끝에서 끝까지 1회 성공했으면 더 깎지 않는다.**

## 절차

### 1. 변경 성격에 맞는 최소 확인을 고른다

| 변경 성격 | 최소 확인 |
| --- | --- |
| 순수 함수·스키마 | 단위 테스트 + 실제 입력 한 건 |
| API·잡·워커 | 실제로 요청/작업을 넣어 상태 전이를 DB·로그에서 본다 |
| UI | **띄워서 눈으로 본다.** 스크린샷을 남긴다. 띄우는 것은 [up](../up/SKILL.md#절차--띄운다-인자-없음) 절차로 — 끝나도 내리지 않는다 |
| 배포·인프라 | 공개 주소에 요청을 보내 응답 코드를 본다 |
| 설정 변경 | **그 설정을 쓰는 그 컨테이너 안에서** 호출해 본다 |
| 문서 산출물 | 만든 파일을 **열어 본다** (렌더 결과·폰트·표 넘침) |

### 2. 설정은 "실제 경로에서" 확인한다

목록 API·문서를 근거로 단정하지 않는다. 같은 대상을 부르는 이름 체계가 둘일 수 있다.

> 실례 셋 — ① 호스트 경로로 바꿨더니 워커가 다른 망이라 타임아웃(단독 실행으로만
> 확인했다). ② 목록 API 의 이름으로 "고쳤더니" 게이트웨이는 별칭을 받아 403.
> ③ 키를 골라 옮기며 하나를 빠뜨려 egress 가 막혔다.
> **셋 다 "확인했다"고 생각한 상태에서 났다.**

### 3. 증거를 파일로 남긴다

`캡처를 저장소(tests/screenshots/)에 남겨줘` 가 반복됐다. 확인은 휘발되므로 남긴다.

- 스크린샷 → 저장소의 테스트 폴더(`tests/screenshots/` 등). 경로를 보고에 적는다
- 결과서를 문서로 달라고 하면 → `docs/verification/<YYYY-MM-DD>-<주제>.md` (`/report` B.4)
- 로그·쿼리 결과 → 결과 문장을 인용한다. 통째로 붙이지 않는다
- **화면을 만들었으면 캡처해서 직접 열어 본다.** 안 보면 빈 화면을 넘기게 된다
- **기존 화면을 고칠 때는 고치기 전에도 찍는다** — `<화면>-before.png`. 변경 후와
  같은 경로·데이터·창 크기로. 지나면 base 를 다시 띄워야 하고, 스키마가 바뀌면 안 뜬다.
  `/report` 의 화면 전후 비교가 이것을 쓴다

### 4. 도구가 없으면 설치하지 말고 스킵한다

e2e 도구가 프로젝트에 없으면 임의로 설치하지 않는다. 통과한 작업을 도구 설치 실패로
실패로 만들지 않는다. **스킵했다고 보고에 적는다.**

## 상한 — 검증은 1라운드

- **보안·데이터 손실만 차단**으로 받는다. 나머지는 **기록만** 한다
- "테스트를 검사하는 테스트" 는 차단이 아니다
- 2라운드를 돌리기 전에 묻는다 — **"이게 제품을 돌게 하는가?"** 아니면 기록한다
- 검증 에이전트는 비싸다(라운드당 10만~18만 토큰). 부르기 전에 같은 질문을 한다
- 사용자가 "빨리"·"그만" 이라고 했으면 라운드를 추가하지 않는다

### 범위를 좁혀 돌린다

- 테스트는 **해당 파일·패키지로 좁혀** 돌린다
- 전체 스위트는 **커밋 직전 한 번만** (`/ship` 의 게이트). 생략하지 않는 이유 —
  "단독이면 통과하고 전체면 깨지는" 스펙이 실제로 있었다
- 출력은 필요한 줄만 뽑는다(`Tests N passed`). 전체 로그를 받지 않는다

### 깨뜨려 보는 검사를 할 때 — 위험은 되돌리는 쪽에 있다

> 무슨 일이 일어나나 — 복원 치환이 **조용히 0건 치환**하고 스크립트는 성공으로
> 끝났다. 그 상태로 다음 검사를 돌려 "초록"을 받았다. **두 번** 났다.

- 백업은 `cp`, **복원도 `cp`** (치환 금지). 한 번에 **하나만** 건다
- 복원 직후 기준 실행을 한 번 더 해 **원래 건수와 같은지** 본다
- 일괄 치환 스크립트는 **치환마다 저장**한다. 끝에 한 번 쓰면 중간 실패에 앞선
  성공까지 날아가는데 성공 로그(`✓`)는 이미 찍혀 있다

## 결정의 결과를 잇는다

이번 확인이 [결정 이력](../go/references/decisions.md)의 어떤 항목을 검증했으면 결과에 증거를
잇고 상태를 `효과 확인` 또는 `문제 발생` 으로 올린다. 의도한 효과를 보지 못했으면 올리지 않는다.

## 보고 — 확인한 것과 안 한 것을 나눈다

**첫 줄은 결론이다** — `된다` · `안 된다` · `일부 (7개 중 5개)`. *"그래서 된다는거야 안된다는거야?"* 가
실제로 나왔다. 사용자에게 직접 보라고 맡기는 항목은 대상·접근·절차·기대 결과를 붙인다
([묻는 형식](../go/references/asking.md)).

```
결론: 일부 (로그인 된다, 웹훅 확인 못 함)

### 확인한 것
| 무엇 | 증거 |
| 로그인 왕복 | 브라우저에서 눌러 세션 쿠키 발급 확인, tests/screenshots/login.png |

### 확인하지 않은 것 — 여기부터 의심한다
- 웹훅 등록: 레포에 훅이 없다
```

**확인하지 못한 것을 통과로 기록하지 않는다.** 이것이 이 단계의 단 하나의 금지다.
"아마 될 것이다"는 확인이 아니다. 추론은 추론이라고 말한다.

## 하면 안 되는 것

- 단위 테스트 초록을 완료로 보고하는 것
- 사용자가 감수하기로 했거나 "언급하지 마" 한 지적(시험 환경의 계정·보안 등)을 확인하지 않은 것 칸에 다시 올리는 것, 로컬 흐름도 확인 전인데 CI·운영 확인을 남은 일로 앞세우는 것 ([제안의 범위](../go/references/proposing.md))
- "정상 동작합니다" 를 실행 없이 쓰는 것
- 확인 못 한 항목을 보고에서 빼는 것 — 빠지면 사용자가 된 줄 안다
- UI 를 만들고 화면을 안 보는 것
- 돌연변이마다 전체 스위트를 돌리는 것
