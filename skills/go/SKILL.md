# 2. 진행한다

입력: `$ARGUMENTS` (비었으면 중단 지점을 복원해 이어간다)

## 왜 이 단계가 있나

`진행해` 계열이 사람이 쓴 메시지에서 **70회 이상** 반복됐다. 단일 최다 지시다.
그 지시를 받을 때마다 "무엇을 진행할까요?" 로 되물어 사용자가 다시 설명해야 했다는
뜻이다. **되묻는 것이 이 지시의 위반이다.**

`진행해` 는 세 가지를 동시에 요구한다.

1. **어디까지 했는지 네가 찾아라** — 사용자는 이미 말했다고 생각한다
2. **다음 한 수를 네가 정하라** — 선택지를 늘어놓지 말라는 뜻이다
3. **지금 시작하라** — 계획을 보고받으려는 게 아니다

## 절차

### 1. 중단 지점을 복원한다 (묻지 않고)

`$ARGUMENTS` 가 있으면 그것이 할 일이다. 없으면 **이 순서로** 본다. 앞에서 답이
나오면 뒤는 건너뛴다.

| 순서 | 무엇을 보나 | 무엇을 얻나 |
| --- | --- | --- |
| 0 | **같은 세션의 직전 응답** — 끝에 제안하거나 물은 것 | 사용자가 "그거 진행해" 로 가리킨 것 |
| 1 | `HANDOFF.md`, `docs/` 의 상태 문서 | 지난 세션이 남긴 "지금 할 일" |
| 2 | `git log --oneline -10` · `git status --short` · 현재 브랜치 | 마지막 커밋이 끝낸 단위, 미커밋 잔여물 |
| 3 | 브랜치 이름 | 작업 단위가 이름에 박혀 있다 (`feature/a2-t45-…`) |
| 4 | 로드맵·계획 문서의 진행 표기 | 다음 단계의 식별자 |
| 5 | TODO·실패하는 테스트 | 손이 멈춘 자리 |

**문서는 자기 자신을 반영하지 못한다.** 인수인계 문서는 커밋 직전에 쓰이므로
"미커밋 변경 둘을 커밋해야 한다" 같은 항목이 **이미 해결된 상태**로 발견된다.
문서를 믿기 전에 `git status` 로 대조한다.

**인계 문서의 할 일이 사용자 결정이면** (머지할지, 공개할지 같은 것) 착수할 수
없다. 결정 대기 항목을 응답 **첫머리에 한 번에** 모아 권고 하나씩과 함께 보이고
([묻는 형식](references/asking.md) — 문서 번호만으로 묻지 않고, 서로 걸린 결정은 앞의 것 하나만),
결정과 무관한 일을 이어 한다. 결정만 남았으면 그렇다고 말하고 끝낸다 — 결정을
추측해 진행하지 않는다.
인계 문서의 `직접:` 항목(사용자만 할 수 있는 콘솔 설정·비밀값 등록·서버 작업)도 착수하지 않는다. 끝났는지
확인할 수 있으면 확인하고, 안 됐으면 같은 첫머리에 무엇·어디서와 함께 한 번 보인다.

**결정은 이력으로 남는다.** 사용자가 답한 결정과 사람 없이 권고대로 진행한 결정을
[결정 이력](references/decisions.md)에 남긴다. 질문 도구의 답은 훅이 쓰고, 대화 문장으로 받은
답은 여기서 쓴다. `진행해` 로 직전 응답의 권고를 받은 것도 결정이다.

**직전 응답이 제안·질문으로 끝났으면 `진행해` 는 그것에 대한 답이다.** 같은 세션 안의
`진행해` 를 새 세션처럼 인계 문서·git 상태부터 복원하면, 사용자가 방금 읽은 제안 대신
문서상 "남은 일" 을 집는다. 2026-10-14 실례 — 직전 응답이 "남겨 둔 두 건을 고칠까요?
그리고 1번을 push 해서 머지할까요?" 로 끝났고 사용자는 고치라는 뜻으로 `/go` 를 불렀는데,
복원 순서가 git 상태에서 "push·머지만 남음" 을 찾아 머지부터 착수했다.

| 직전 응답이 제안·질문한 것 | `진행해` 가 뜻하는 것 |
| --- | --- |
| 워크트리 안의 일 하나 (수정·구현·검증) | 그 일 |
| 안의 일과 push·PR·merge 를 함께 (물었든, "그 다음은 …"·"남은 것" 으로 적었든) | **둘 다, 안의 일 먼저.** 안의 일을 끝내고 게이트가 초록이면 다시 묻지 않고 push·PR·merge 를 잇는다 |
| push·PR·merge 만 | 그 작업 |
| 선택지 여럿 중 하나 고르기 | 직전 응답이 권고한 것. 권고가 없었으면 그때만 묻는다 |

**직전 응답이 권고한 push·PR·merge 는 `진행해` 로 승인된 것이다.** 사용자는 제안을 읽고
`진행해` 로 받았다. 안의 일만 하고 "push 할까요?" 를 다시 물으면 같은 답을 두 번 받게 된다.
2026-11-12 실례 — 직전 응답이 남은 일과 push·PR 을 함께 적었고 사용자가 `/go` 를 불렀는데,
남은 일만 하고 push·PR 은 하지 않았다. 사용자가 *"push, pr 등이 있어서 수행을 안했기 때문에"*
되물었다.

순서와 한계:

1. **안의 일이 먼저다.** 2026-10-14 실례 — 직전 응답이 "남겨 둔 두 건을 고칠까요? 그리고 1번을 push 해서
   머지할까요?" 로 끝났는데 `/go` 가 머지부터 착수했다. 고칠 것이 들어가지 않은 채 나간다
2. **안의 일이 끝나지 않았거나 게이트가 빨가면 내보내지 않는다.** 막힌 지점과 함께 보고하고 멈춘다
3. 내보내기는 [ship 의 5단계](../ship/SKILL.md#5-바깥으로-내보낸다-인자가-있을-때만) 그대로 —
   원격을 다시 보고, 한 뒤 실제 주소로 확인한다
4. **직전 응답·인계 문서의 "지금 할 일" 에 적힌 것만 한다.** 적히지 않은 push·merge 를 git 상태만 보고
   새로 하지 않는다. 인계 문서의 **결정 대기**에 있는 것은 위 결정 규칙대로 묻는다
5. **배포·운영 DB·외부 발송은 이 승인에 들지 않는다.** `CLAUDE.md` 가 기본 브랜치 push 를 운영 배포라고
   적은 저장소면 merge 도 여기에 든다 — 그 작업만 따로 한 번 묻는다

### 2. 에이전트 운영이 정해졌는지 본다

`CLAUDE.md` 의 `## 에이전트 운영` 절이나 `docs/team.md` 가 있으면 그대로 따른다 —
팀이면 `team run` 으로 위임하고, 단일이면 직접 한다. 팀이면 **첫 디스패치 전에 작업
공간 목록을 명단과 대조한다** — 중단 전의 워커 공간이 남아 있다. 비어 있는 공간에
디스패치하고 병합 끝난 일감 공간은 걷는다 ([team 규칙 6](../team/references/delegation.md#규칙-6--워커는-작업-공간-하나다-일감마다-새로-만들지-않는다)).

**둘 다 없으면 착수 전에 한 번 묻고 그 턴을 끝낸다.** `start`·`team` 을 거치지 않은
저장소다. 파일을 고치기 시작한 뒤에 묻지 않는다 — 단일이냐 팀이냐에 따라 누가
고칠지가 달라진다. 아래 4단계의 "막혔으면 나머지를 끝낸다" 는 여기에 적용하지 않는다.
[team 의 운영 결정](../team/SKILL.md#운영-결정--단일인가-팀인가) 형식대로 분석
결과와 권고 하나로 묻고, 답을 기록한 뒤 이어간다. 이 질문은 "되묻기" 가 아니다 —
저장소당 한 번이고, 기록이 남아 다시 묻지 않는다.

**저장소 파일을 바꾸지 않는 요청은 묻지 않고 한다** — 분석·조사·상태 확인·검토처럼
결과가 대화창 보고로 끝나는 일. 누가 고칠지가 걸리지 않기 때문이다(`team` 절대 규칙
2 의 "읽기·조사" 예외와 같다). 그 결과를 고치는 일로 넘어갈 때 묻는다 — 분석 보고
끝에 운영 질문을 붙여 한 턴에 낸다.

### 3. 선행 조건이 비어 있는지 본다

문서가 "다음은 X" 라고 적어도, X 가 부르는 대상이 아직 없을 수 있다. **X 의 정의에
등장하는 함수·모듈·테이블이 실제로 존재하는지 grep 으로 확인한다.** 없으면 그
선행 단계가 진짜 다음 한 수다.

> 실례 — 문서는 "다음은 T45(프로필 기반 실행)" 라고 적었지만 T45 가 호출할
> `AgentEngine.run()` 이 인터페이스에 없었다. 선행 단계가 절반 남아 있었다.

### 4. 한 수를 정해 바로 착수한다

- 다음 한 수를 **한 문장으로** 말하고 시작한다. 승인을 기다리지 않는다
- 다음 할 일·권고·결정 대기를 적을 때는 [제안의 범위](references/proposing.md)를 따른다 — 결정 이력과
  `CLAUDE.md` 를 먼저 읽고, 정한 것은 다시 꺼내지 않고, 지금 단계(`## 배포`)보다 앞선 배포·CI 는 권하지 않는다
- 선택지가 둘 이상이고 **결과가 실질적으로 달라질 때만** [묻는 형식](references/asking.md)으로 묻는다. 그 경우에도
  먼저 답에 의존하지 않는 부분을 다 해 놓는다
- 막혔으면 막힌 지점을 적고 **나머지를 끝낸다**. 전체를 세워 두지 않는다
- 버그·실패를 만나면 `/fix` 규칙으로 전환한다 — 증상부터 덮지 않는다
- 분석·설계·가이드 같은 문서를 만드는 일이면 `CLAUDE.md` 의 `## 문서 자리`, 없으면
  [report 의 B.4](../report/SKILL.md#4-어디에-두나--프로젝트-docs-를-요청-종류로-나눈다) 폴더에 둔다

### 5. 끝까지 몰고, 끝을 알린다

`끝나면 알려줘`(4회), `qa 끝나면 갭 수정까지 바로 진행해`(3회) 가 반복됐다.
**단계 경계는 멈출 자리가 아니다.** 한 단위를 끝까지 몰아 `/check` 로 확인하고
끝났다고 알린다. 처음부터 끝까지 한 번에 맡긴 것이면 `/auto` 다.

## 자율 범위 — 어디까지 묻지 않는가

사용자가 명시했다 — *"워크스페이스 내에 있는 파일 처리 및 명령어 수행은 사람에게
확인 받지 말고 알아서 처리하라"*. 같은 지시가 두 번 나왔다.

판단 기준은 **되돌리기 쉬운가**가 아니라 **워크트리 밖으로 번지는가**다.

### 묻지 않는다 (워크트리·워크스페이스 내부)

- 파일·디렉터리 삭제, 덮어쓰기, 이동
- 도커 컨테이너·이미지·볼륨·네트워크 생성 및 삭제, 컴포즈 up/down
- 프로세스 종료 (개발 서버·워커), 패키지 제거
- 셸 명령 수행, 스크립트 작성·실행, 로컬 커밋, 브랜치 생성

**하고 나서 무엇을 했는지 보고에 적는다.** 묻지 않는 대가가 보고다.

### 묻는다 (워크트리 밖으로 번진다)

| 무엇 | 왜 |
| --- | --- |
| 원격 push · PR · merge · 배포 | `master` push 가 운영 배포인 저장소가 있다 |
| 운영 DB 의 모든 DDL·DML | 되돌릴 수 없다. 운영 DB 를 날린 기록이 있다 |
| 머신 전역 정리 (`docker system prune` 등) | 다른 프로젝트의 이미지·볼륨까지 지운다 |
| 전역 패키지 관리자 | 워크트리와 무관한 머신 상태다 |
| 권한·설정 자체 (`~/.claude/settings.json`) | 이후 모든 판단의 전제를 바꾼다 |
| 외부 서비스로 내보내기 (메일·메시지·웹훅) | 캐시·색인에 남아 회수되지 않는다 |
| 원격 서버의 공용 자원, 비밀번호·키 교체, 저수준 쓰기 | 잠금·장치 손상 위험 |

**경계에 걸리면** 워크트리 안의 일 전부를 먼저 끝내고, 바깥 작업만 모아 **한 번에,
권고 하나와 사유 한 줄로** 묻는다. 직전 응답이 이미 권고한 push·PR·merge 를 `진행해` 로 받았으면
다시 묻지 않는다 (1단계 표). 작업을 세워 두고 묻지 않는다.

### 묻지 않는 범위라도 백업은 남긴다

- 설정 파일을 고치기 전 `cp` 로 타임스탬프 백업
- 많은 파일을 지우기 전 지울 목록을 먼저 출력해 센다
- 추적 파일을 지웠으면 보고에 **git 영향**을 적는다

### 거부 반복

같은 요청을 사용자가 **재확인**했으면 그것은 결정이다. 우려를 한 문장으로 전하고
**전체 요청을 수행한다.** 같은 우려를 두 번 말하지 않는다.

## 하면 안 되는 것

- "어디부터 진행할까요?" 로 시작하는 응답
- 복원한 상태를 길게 요약하고 끝내는 것. 요약은 착수의 부산물이다
- 선택지 네 개를 표로 만들어 고르게 하는 것
- `D-1·D-2 결정해 주세요` 처럼 문서 번호로 묻거나, 무엇을 어디서 볼지 없이 "확인해 주세요" 라고 하는 것
- 문서에 적힌 "다음" 을 검증 없이 착수하는 것
- 같은 세션에서 직전 응답의 제안을 건너뛰고 문서·git 상태의 "남은 일" 을 집는 것
- 안의 일과 push·머지를 함께 받은 뒤 push·머지부터 하는 것
- 직전 응답이 권고한 push·PR·merge 를 안의 일만 끝내고 다시 묻는 것
- 사용자가 거절했거나 "그냥 둬" 라고 한 것을 다음 권고로 다시 올리는 것, 로컬 구현 중에 배포를 권하는 것
- 같은 파일을 3회 이상 왕복하며 다듬는 것 — 멈추고 기록한다

확인한 것 / 확인하지 않은 것, 그리고 **직접 하실 일**. 외부 콘솔 설정·비밀값 등록·서버 작업처럼 사용자만 할 수 있는
일이 생겼으면 본문에 섞지 말고 끝에 [직접 하실 일](../report/SKILL.md#직접-하실-일--사용자만-할-수-있는-일은-보고-끝에-한-곳으로)
