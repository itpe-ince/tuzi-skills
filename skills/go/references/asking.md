# 묻는 형식 — 질문만 읽고 답할 수 있게

사용자에게 결정·확인을 청하는 모든 자리(`go`·`spec`·`check`·`handoff`·`start`·`team`·`auto`)가 이 형식을 따른다.

## 왜

2026-10-05 ~ 11-12 사람이 쓴 메시지 중 **약 26건(프로젝트 6개)이 질문을 되물은 것**이다
(`docs/analysis/2026-11-12-memory-prompt-review.md` 2.1).

> *"D-1·D-2가 뭔데? 제발 선택지 물어볼때는 너만 아는 아이디로 나한테 어떻게 해야 하냐구 물어보지마."*
> *"휴대폰에서 도대체 뭘 어떻게 확인하냐구. 대상, 접속방법은 하나도 안알려주고 뭘하라는거야?"*
> *"그래서 파일 포맷별 파일 편집 기능들이 잘 된다는거야 안된다는거야?"*

설계서의 결정 목록·결정 이력은 번호(D-1, R-07, N-12)로 색인한다. 그 번호가 질문에 그대로 올라오면
사용자는 문서를 열어야 답할 수 있다. **번호는 문서 안의 색인이지 질문의 주어가 아니다.**

## 결정을 물을 때

```
**<무엇을 정하나 — 번호 없이 읽히는 한 문장>**
- 왜 지금: <이 답이 없어 무엇이 멈춰 있나, 한 줄>
- (a) <선택지> → <사용자가 보거나 겪는 결과>
- (b) <선택지> → <〃>
- 권고: (a) — <이유 한 줄>
```

1. **문서 번호만으로 가리키지 않는다.** 번호를 남기려면 문장 뒤 괄호에 둔다 — `복구 코드를 언제 줄지 (설계서 D-2)`.
   답을 번호로 달라고 하지 않는다
2. **결과는 사용자 쪽 말로 쓴다** — 화면·데이터·비용·되돌리기 가능 여부. 구현 내부(`ImageToken 재설계`)가 아니다.
   처음 나오는 전문어(슬라이스, 그랜트)는 한 마디로 풀거나 쓰지 않는다
3. **서로 걸린 결정은 앞의 것 하나만 묻는다.** 뒤의 답이 앞의 답에 달려 있으면 함께 물을 때 둘 다 복잡해진다.
   뒤의 것은 `이 답에 따라 다음에 물을 것: <한 문장>` 으로 한 줄만 둔다. 서로 독립이면 함께 보여도 되고, 각각 위 모양으로 쓴다
4. 권고가 없으면 없다고 쓰고, 고를 근거가 될 사실 하나를 적는다

## 확인·작업을 맡길 때

사용자가 직접 보거나 해야 하는 일이면 다섯 가지를 다 적는다.

| 칸 | 예 |
| --- | --- |
| 대상 | 휴대폰의 게임 화면 · `.env.staging` 의 `JWT_SECRET` |
| 접근 | `http://192.168.0.71:5173/?debug=1` · 서버 `ssh gx10` 후 `/app/x` |
| 절차 | 창 버튼을 두 번 누른 뒤 공격 |
| 기대 결과 | 창이 날아가 꽂힌 자리에 표시가 남는다 |
| 다르면 | 무엇이 보였는지 한 줄로 알려 주시면 됩니다 |

## 결과를 보고할 때

**첫 줄에 결론을 쓴다** — `된다` · `안 된다` · `일부 (7개 중 5개)`. 근거와 예외는 그 아래다.

## 고치기 전과 후

```
고치기 전
| D-1 | 공유 파일 암호화 키를 어디에 보관할지 | (a) 서버 (b) 사용자 기기만 | (a) |
| D-2 | 복구 코드를 언제 발급할지 | (a) 가입 시 (b) 첫 공유 시 | (a) |
"D-1 a, D-2 a" 처럼 답해 주세요.

고친 뒤
**공유 파일을 여는 열쇠를 서버에도 둘까요?**
- 왜 지금: 공유 대화상자 화면을 이 답 없이 그릴 수 없습니다
- (a) 서버에도 둔다 → 여러 사람이 같은 파일을 동시에 편집할 수 있다. 서버 관리자도 파일을 열 수 있다
- (b) 사용자 기기에만 둔다 → 서버 관리자도 못 연다. 동시 편집은 안 되고, 기기를 잃으면 복구 코드가 있어야 연다
- 권고: (a) — 설계서가 동시 편집을 필수로 적었습니다
이 답에 따라 다음에 물을 것: 복구 코드를 언제 드릴지 (설계서 D-2)
```

## 하면 안 되는 것

- `D-1·D-2 결정해 주세요` 처럼 번호만 늘어놓는 것
- `확인해 주세요` 만 쓰고 무엇을 어디서 볼지 빼는 것
- 서로 걸린 결정 셋을 한 표에 넣고 한꺼번에 고르게 하는 것
- 결론 없이 근거부터 늘어놓는 보고
