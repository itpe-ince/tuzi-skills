# 결정 이력 — 무엇을 골랐고 어떻게 됐나

사용자가 나중에 **그때 무엇을 골랐고, 그게 어떤 결과로 이어졌는지** 볼 수 있게 남긴다.
인계 문서는 미결만 담고 덮어쓰이므로 이 자리가 아니다.

## 자리

저장소 루트에 `DECISIONS.md` 가 있으면 그것, 없으면 `docs/decisions.md`.

## 항목

```markdown
## D-261104-1532 머지 방식

- 결정일: 2026-11-04
- 질문: PR 을 어떤 방식으로 합칠까요?
- 선택 항목: Merge / Squash
- 권고: Merge
- 채택: Squash
- 결정자: 사용자
- 이유: 미기재
- 결과: PR #12 로 반영 (`ab12cd3`)
- 상태: 반영됨
```

앞의 일곱 칸은 답을 받을 때, 결과와 상태는 일이 진행되면서 채운다.

## 언제 누가 쓰나

| 시점 | 할 일 | 수단 |
| --- | --- | --- |
| 질문 도구로 답을 받았을 때 | 항목 추가 | **훅이 자동으로 쓴다.** 손으로 또 쓰지 않는다. 답과 함께 이유를 들었으면 이유 칸만 채운다 |
| 대화 문장으로 답을 받았을 때 | 항목 직접 추가. 선택 항목은 직전 응답에서 옮긴다 | `go` 등 그 턴의 스킬 |
| 사람 없이 권고대로 진행했을 때 | 항목 직접 추가, 결정자 `AI 권고로 진행` | `auto`·`go` |
| 커밋·PR·머지 | 관련 항목의 결과에 커밋·PR 을 잇고 상태를 올린다. 파일을 같은 커밋에 넣는다 | `ship` |
| 검증 | 결과에 증거를 잇고 상태를 올린다 | `check` |
| 상태 확인 | 오래 대기·결과 미기재·추인 필요를 보고한다 | `scan` |

## 상태

| 상태 | 뜻 |
| --- | --- |
| 대기 | 정했지만 아직 반영 전 |
| 반영됨 | 코드·설정·문서에 들어갔다. 효과는 아직 모른다 |
| 효과 확인 | 의도한 결과가 났다. 증거가 있어야 한다 |
| 문제 발생 | 반영했더니 문제가 났다. 무엇이 어떤지 적는다 |
| 번복 | 다른 결정으로 바뀌었다. `D-…로 번복` 을 적는다 |
| 일회성 | 그 자리에서 끝나 추적할 결과가 없다 (머지 방식, 이번 실행 여부 등) |

## 규칙

- **결과에는 근거를 붙인다** — PR·커밋·검증 문서. 확인하지 못했으면 `결과 미확인` 이라고 적는다. 지어내지 않는다
- **덮어쓰지 않는다** — 바꾸면 새 항목을 쓰고, 옛 항목 상태를 `번복` 으로 바꾼다
- **결정자를 속이지 않는다** — `AI 권고로 진행` 은 사용자가 추인하면 `사용자 (추인 <날짜>)` 로 바꾼다
- **비밀 값을 적지 않는다** — 키·비밀번호는 이름만
- 과거 결정을 소급해서 옮기지 않는다. 요청받았을 때만 한다
