# 제안의 범위 — 지금 단계, 이 프로젝트, 아직 정하지 않은 것만

다음 할 일·권고·한계·결정 대기를 적는 모든 자리(`go`·`check`·`spec`·`bench`·`handoff`·`auto`·`report`)가 이 규칙을 따른다.

## 왜

2026-10-05 ~ 11-12 사람이 쓴 메시지 10건과 메모리 8건이 같은 모양이다 — **사용자가 한 번 정한 것을 AI 가 다시 꺼냈다**
(`docs/analysis/2026-11-12-memory-prompt-review.md` 2.4). 메모리는 그 뒤에 남은 흔적이다.

> *"지금 로컬에서 구현 중인대 운영 배포가 시급한가?"* · *"완료도 안됐는데 왜 계속 배포하래?"*
> *"아직 로컬에서도 기능 점검을 하지 않았는데 CI를 돌려보지 못했다는 문제는 언급하긴 시기상조야."*
> *"이 솔루션을 폐쇄망에 적용한다는 제안은 제시한 적이 없어."* · *"벤치마크 분석에서 왜 계속 uscp를 언급하는지 모르겠어."*
> *"내가 내부에서 쓰는 보고서라 긁어도 상관 없다고 몇번이나 얘기해야 해?"*

실패는 세 모양이다.

| 모양 | 실례 |
| --- | --- |
| 지금 단계보다 앞선 일을 권한다 | 로컬 구현 중에 단계마다 "배포하시겠습니까", 로컬 흐름도 안 돈 상태에서 CI·push 제안 |
| 다른 프로젝트의 조건을 끌어온다 | 다른 저장소의 운영 환경(폐쇄망)·연동 대상(USCP)을 이 프로젝트의 제약·한계로 적음 |
| 사용자가 정했거나 사용자 몫인 판단을 다시 꺼낸다 | "그냥 내버려 둬" 한 설정을 다시 고치자고 함. 테스트 DB 계정 보안, 내부 보고서의 수집 약관을 매번 지적 |

## 제안하기 전에 읽는다

| 무엇 | 거기서 찾는 것 |
| --- | --- |
| [결정 이력](decisions.md) (`docs/decisions.md`) | 같은 주제의 결정. 채택이 `하지 않는다`·`그대로 둔다` 이거나 `번복` 이 아닌 결정이 있으면 그 답이 아직 유효하다 |
| `CLAUDE.md` 의 「하면 안 되는 것」 · `## 배포` | 하지 말라고 한 것, 배포를 언제·얼마나 조심해서 하는지 |
| 이 대화에서 사용자가 한 말 | 방금 정한 범위·우선순위 |

## 규칙

1. **정한 것은 다시 꺼내지 않는다.** 결정 이력·`CLAUDE.md`·대화에 답이 있으면 그 주제를 권고·한계·결정 대기에 올리지 않는다.
   사용자가 다시 꺼낼 때만 다룬다. 정한 뒤로 사실이 바뀌었으면(사고가 났다, 전제가 깨졌다) 무엇이 바뀌었는지 한 줄과 함께
   한 번만 묻는다
2. **지금 단계에 맞는 것만 권한다.** 단계는 `CLAUDE.md` 의 `## 배포` 나 사용자가 말한 우선순위가 정한다
   - `## 배포` 가 "로컬 전체 완료 뒤" 처럼 시점을 적었으면 그 전에는 배포·운영 확인을 권하지 않고, 결정 대기에도 올리지 않는다.
     확인은 로컬 수단을 먼저 찾는다
   - `## 배포` 가 "민감하지 않다" 고 적었으면 배포 요청에 경고·재확인 질문을 붙이지 않는다. 배포를 **할지**는 여전히
     사용자가 말할 때다 — 민감도는 요청을 받은 뒤의 태도이지 승인이 아니다
   - 절이 없으면 배포는 사용자가 말할 때만 꺼낸다. push·PR 은 작업 단위가 끝났을 때 한 번 묻는다
   - **예외는 보안 사고·데이터 손실·운영 장애뿐이다.** 그때는 단계와 무관하게 한 줄로 알린다
3. **전제는 이 저장소의 문서와 사용자의 말에서만 가져온다.** 다른 프로젝트의 메모리·문서·이전 대화에서 본 조건(운영 환경·
   연동 대상·고객 요구)을 이 프로젝트의 제약이나 한계의 근거로 쓰지 않는다. 관련이 있어 보이면 "다른 프로젝트(<이름>)의 조건인데
   여기에도 해당하나요" 로 한 번 묻는다
4. **위험 판단이 사용자 몫인 것은 사실만 적는다.** 내부용 자료의 수집 범위·약관, 시험용 환경의 계정·보안처럼 사용자가 감수하기로
   한 것은 "기술적으로 되나" 만 보고하고, 그것을 이유로 범위를 자르거나 매번 경고하지 않는다. 사용자가 "언급하지 마" 라고 했으면 쓰지 않는다
5. **거절도 기록한다.** 사용자가 제안을 거절하거나 "그냥 둬" 라고 하면 결정 이력에 채택 `하지 않는다` 로 남긴다 —
   다음 세션이 이 규칙 1 로 읽는다

## `CLAUDE.md` 의 `## 배포`

`start` 가 뼈대에 넣는다. 사용자가 배포 시점·조심할 정도를 말하면 그 자리에서 고친다.

```markdown
## 배포
- 시점: <로컬에서 전체 요구 구현이 끝난 뒤 한 번 | 작업 단위마다 | 사용자가 말할 때>
- 민감도: <정식 운영 전 — 경고·재확인 없이 | 운영 중 — 대상·영향을 보이고 묻는다>
- 방법: <`git push origin HEAD:main` → Actions → https://… 확인>
```

## 하면 안 되는 것

- 로컬 구현 중인 단계 보고 끝마다 배포·CI 를 권하는 것
- "그냥 둬" 라고 한 설정을 다음 보고의 개선 후보로 다시 올리는 것
- 다른 저장소에서 본 운영 조건을 이 프로젝트의 한계로 적는 것
- 사용자가 감수하기로 한 위험을 보고마다 다시 경고하는 것
