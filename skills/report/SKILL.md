# 4. 보고한다

입력: `$ARGUMENTS` (형식. 비었으면 대화창에 보고한다)

## 왜 이 단계가 있나

`보고` 가 사람이 쓴 메시지의 **9.7%(132건)** 로 2위, `만들` 이 100건, `문서` 가 27건이다.
보고가 일을 덜어 주지 못하면 사용자는 결국 디프를 직접 연다 — 그때 보고는 비용이지
산출물이 아니다.

## A. 변경 보고 — 네 규칙

### 1. 없는 식별자를 만들지 않는다

> 무슨 일이 일어나나 — 사용자가 준 적 없는 "Task 1", "Req A", "Phase 2" 를 지어내
> 근거처럼 인용한다. 읽는 사람은 그런 번호를 찾으러 간다. 없다.

근거로 인용할 번호는 저장소의 **실제** 문서·이슈·티켓에 있는 것만 쓴다. 인용하기 전에
`grep` 으로 있는지 본다. 없으면 번호 없이 서술한다.

### 2. [파일명] · [기존 동작] · [변경 후 동작] 을 대조한다

**"기존 동작"은 코드 모양이 아니라 동작이다** — "함수가 20줄이었다"가 아니라
"만료를 검사하지 않았다".

| 파일 | 기존 동작 | 변경 후 동작 |
| --- | --- | --- |
| `auth/session.ts` | 만료를 검사하지 않아 지난 토큰도 통과했다 | `exp` 를 현재 시각과 대조해 지난 토큰을 거부한다 |

### 3. 이유와 영향 파일을 함께 밝힌다

수정 이유를 적고, 영향받는 파일을 명시한다 — 호출부·임포트·설정·테스트까지.
**영향이 없으면 "없음"이라고 적는다.** 빈칸은 "안 봤다"와 구별되지 않는다.

### 4. 적기 전에 파일과 대조한다

> 무슨 일이 일어나나 — "고쳤다"고 적었는데 파일에 없었다. 치환 스크립트가 중간에
> 죽었는데 성공 로그(`✓`)는 이미 출력돼 있었다.

- `git diff --stat` / `git show --stat HEAD` 로 **의도한 파일만 들었는지** 본다
- 새 ID·새 행을 넣었으면 `grep` 으로 결과를 확인한다

### 뼈대

```
## 무엇을 했나
(한 문단. 결과부터)

| 파일 | 기존 동작 | 변경 후 동작 |
| --- | --- | --- |

**이유** — …
**영향 파일** — 호출부 `x.ts`, 테스트 `x.test.ts`. (또는 "없음")

## 확인한 것 / 확인하지 않은 것
(/tuzi:check 의 두 칸)
```

버그 수정이면 `/tuzi:fix` 의 **원인 · 같은 패턴 · 강제자** 세 줄을 덧붙인다.

### 형식 규칙

- **텍스트 디프를 통째로 붙이지 않는다.** 표가 기본, 폴더 단위 요약은 ASCII 트리,
  영향 범위가 핵심일 때만 흐름도. 추론으로 그린 선은 추론이라고 말한다
- 오타·1줄 수정은 **한 줄로** 보고한다. 표를 만들지 않는다
- 사용자에게 하는 보고는 **존댓말·평이한 설명체**다. 저장소 문서의 압축된 문체를
  옮기지 않는다

## B. 문서 산출물

### 1. 폰트 — Pretendard

`html` · `pptx` · `docx` · `xlsx` · `pdf` 의 **본문 폰트는 Pretendard**. 코드 블록은
모노스페이스를 유지한다. 사용자가 다른 폰트를 지정하면 그것이 우선한다.

폴백 스택 — **항상 함께** 지정한다.

```
Pretendard, "Pretendard Variable", -apple-system, BlinkMacSystemFont,
"Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif
```

| 포맷 | 어떻게 넣나 |
| --- | --- |
| HTML | CDN 웹폰트를 `<link>` 로 불러오고 `body { font-family: … }` 에 위 스택 |
| pptx | 텍스트 런마다 폰트 지정 + **한글은 East Asian(`a:ea`) 속성까지** |
| docx | 스타일 폰트 + **`w:eastAsia` 속성**을 함께 |
| xlsx | 셀/스타일에 폰트 이름 |
| pdf | HTML→PDF 면 HTML 규칙 그대로. 직접 생성이면 TTF 를 등록해 임베드 |

CDN: `https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css`

**적용됐다고 단정하지 않는다.** 머신에 Pretendard 가 없으면 pptx·docx·xlsx 는 이름만
박히고 미리보기는 폴백으로 렌더된다. 확인하고, 없으면 그 사실을 보고에 적는다.

```bash
ls ~/Library/Fonts /Library/Fonts 2>/dev/null | grep -i pretendard   # macOS
```

### 2. 정본 문서를 갱신하는 요청은 새 문서가 아니다

`docs/X.md 에 반영해줘`·`로드맵 재편해줘`:

- 기존 문서의 **구조와 문체를 따른다.** 새 절을 끼워 넣을 자리를 먼저 찾는다
- 문서가 스펙이면 요청이 문서와 **어긋나는지** 먼저 본다. 모순이면 사람에게 알린다
- 문서가 코드와 어긋난 채 남은 곳을 발견하면 보고에 적는다. 조용히 고치지 않는다

### 3. 변환 (`.md` → 워드·PDF)

원본을 그대로 옮기지 않는다. 제목 단계·표·코드 블록이 그 포맷에서 어떻게 보이는지
맞추고, 넘치는 표는 쪼갠다. 만든 뒤 **열어 본다** (`/tuzi:check`).

### 4. 어디에 두나

| 요청 | 자리 |
| --- | --- |
| 저장소의 정본 문서 | `docs/` 아래 기존 체계 |
| 확인 증거(스크린샷·결과서) | 테스트 폴더 (`tests/screenshots/` 등) |
| 중간 산출물·임시 변환 | 스크래치패드. 저장소에 남기지 않는다 |

사용자가 경로를 지정했으면 그대로 쓴다. **경로를 보고에 적는다.**
