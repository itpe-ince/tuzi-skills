# 4. 보고한다

입력: `$ARGUMENTS` (형식. 비었으면 대화창에 보고한다)

## 왜 이 단계가 있나

`보고` 가 사람이 쓴 메시지의 **9.7%(132건)** 로 2위, `만들` 이 100건, `문서` 가 27건이다.
보고가 일을 덜어 주지 못하면 사용자는 결국 디프를 직접 연다 — 그때 보고는 비용이지
산출물이 아니다.

## A. 변경 보고 — 네 규칙

### 1. 없는 식별자를 만들지 않는다

> 무슨 일이 일어나나 — 사용자가 준 적 없는 "Task 1", "Req A", "Phase 2" 를 지어내
> 근거처럼 인용한다. 읽는 사람은 그런 번호를 찾으러 간다. 없다.

근거로 인용할 번호는 저장소의 **실제** 문서·이슈·티켓에 있는 것만 쓴다. 인용하기 전에
`grep` 으로 있는지 본다. 없으면 번호 없이 서술한다.

### 2. [파일명] · [기존 동작] · [변경 후 동작] 을 대조한다

**"기존 동작"은 코드 모양이 아니라 동작이다** — "함수가 20줄이었다"가 아니라
"만료를 검사하지 않았다".

| 파일 | 기존 동작 | 변경 후 동작 |
| --- | --- | --- |
| `auth/session.ts` | 만료를 검사하지 않아 지난 토큰도 통과했다 | `exp` 를 현재 시각과 대조해 지난 토큰을 거부한다 |

### 3. 이유와 영향 파일을 함께 밝힌다

수정 이유를 적고, 영향받는 파일을 명시한다 — 호출부·임포트·설정·테스트까지.
**영향이 없으면 "없음"이라고 적는다.** 빈칸은 "안 봤다"와 구별되지 않는다.

### 4. 적기 전에 파일과 대조한다

> 무슨 일이 일어나나 — "고쳤다"고 적었는데 파일에 없었다. 치환 스크립트가 중간에
> 죽었는데 성공 로그(`✓`)는 이미 출력돼 있었다.

- `git diff --stat` / `git show --stat HEAD` 로 **의도한 파일만 들었는지** 본다
- 새 ID·새 행을 넣었으면 `grep` 으로 결과를 확인한다

### 뼈대

```
## 무엇을 했나
(한 문단. 결과부터)

| 파일 | 기존 동작 | 변경 후 동작 |
| --- | --- | --- |

**이유** — …
**영향 파일** — 호출부 `x.ts`, 테스트 `x.test.ts`. (또는 "없음")

## 확인한 것 / 확인하지 않은 것
(/check 의 두 칸)
```

버그 수정이면 `/fix` 의 **원인 · 같은 패턴 · 강제자** 세 줄을 덧붙인다.
영향 파일에 스키마·화면이 들었으면 **C 절**(ERD 차이 · 화면 전후 비교 · 신규 화면 설명서)을 덧붙인다.

### 형식 규칙

- **텍스트 디프를 통째로 붙이지 않는다.** 표가 기본, 폴더 단위 요약은 ASCII 트리,
  영향 범위가 핵심일 때만 흐름도. 추론으로 그린 선은 추론이라고 말한다
- 오타·1줄 수정은 **한 줄로** 보고한다. 표를 만들지 않는다
- 사용자에게 하는 보고는 **존댓말·평이한 설명체**다. 저장소 문서의 압축된 문체를
  옮기지 않는다
- 보고 끝의 다음 할 일·권고는 [제안의 범위](../go/references/proposing.md)를 따른다 — 이미 정한 것,
  지금 단계보다 앞선 배포·CI, 다른 프로젝트의 조건을 올리지 않는다

## B. 문서 산출물

### 1. 폰트 — Pretendard

`html` · `pptx` · `docx` · `xlsx` · `pdf` 의 **본문 폰트는 Pretendard**. 코드 블록은
모노스페이스를 유지한다. 사용자가 다른 폰트를 지정하면 그것이 우선한다.

폴백 스택 — **항상 함께** 지정한다.

```
Pretendard, "Pretendard Variable", -apple-system, BlinkMacSystemFont,
"Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif
```

| 포맷 | 어떻게 넣나 |
| --- | --- |
| HTML | CDN 웹폰트를 `<link>` 로 불러오고 `body { font-family: … }` 에 위 스택 |
| pptx | 텍스트 런마다 폰트 지정 + **한글은 East Asian(`a:ea`) 속성까지** |
| docx | 스타일 폰트 + **`w:eastAsia` 속성**을 함께 |
| xlsx | 셀/스타일에 폰트 이름 |
| pdf | HTML→PDF 면 HTML 규칙 그대로. 직접 생성이면 TTF 를 등록해 임베드 |

CDN: `https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css`

**적용됐다고 단정하지 않는다.** 머신에 Pretendard 가 없으면 pptx·docx·xlsx 는 이름만
박히고 미리보기는 폴백으로 렌더된다. 확인하고, 없으면 그 사실을 보고에 적는다.

```bash
ls ~/Library/Fonts /Library/Fonts 2>/dev/null | grep -i pretendard   # macOS
```

**HTML 의 다이어그램은 렌더러까지 넣는다.** md 뷰어는 ` ```mermaid ` 를 그려 주지만
HTML 은 아무것도 그려 주지 않는다 — `<pre class="mermaid">` 만 두면 화면에 소스 텍스트가
그대로 나온다(2026-10-12, `flowchart LR` 4개가 텍스트로 노출). 다이어그램을 넣었으면
Mermaid 스크립트(CDN `cdn.jsdelivr.net/npm/mermaid@11`)를 불러와 실행하고, 이 스킬 폴더의
스크립트로 **블록마다 SVG 로 바뀌었는지** 확인한다. 새로 짜지 않는다.

```bash
python3 <이 스킬 폴더>/scripts/check_mermaid.py <html 파일>...
```

| 종료 코드 | 뜻 | 보고 |
| --- | --- | --- |
| 0 | 전부 그려짐 | 스크립트 출력(블록 수)을 근거로 적는다 |
| 1 | 안 그려졌거나 문법 오류 | 고치고 다시 돌린다 |
| 2 | 브라우저가 없거나 열지 못함 | **미확인**이라고 적는다. 브라우저를 설치하지 않는다 |

### 2. 정본 문서를 갱신하는 요청은 새 문서가 아니다

`docs/X.md 에 반영해줘`·`로드맵 재편해줘`:

- 기존 문서의 **구조와 문체를 따른다.** 새 절을 끼워 넣을 자리를 먼저 찾는다
- 문서가 스펙이면 요청이 문서와 **어긋나는지** 먼저 본다. 모순이면 사람에게 알린다
- 문서가 코드와 어긋난 채 남은 곳을 발견하면 보고에 적는다. 조용히 고치지 않는다

### 3. 변환 (`.md` → 워드·PDF)

원본을 그대로 옮기지 않는다. 제목 단계·표·코드 블록이 그 포맷에서 어떻게 보이는지
맞추고, 넘치는 표는 쪼갠다. 만든 뒤 **열어 본다** (`/check`).

### 4. 어디에 두나 — 프로젝트 `docs/` 를 요청 종류로 나눈다

문서는 **그 프로젝트의 `docs/` 아래, 요청 종류별 폴더**에 둔다. 한 폴더에 섞으면
보고서와 설계서와 설명서가 날짜순으로만 쌓여 다시 찾을 수 없다.

| 요청 | 폴더 | 예 |
| --- | --- | --- |
| 분석 | `docs/analysis/` | 현황·요구사항·원인 분석, 영향도 조사 |
| 설계 | `docs/design/` | 아키텍처, ERD, API·화면 설계 |
| 구현 | `docs/implementation/` | 구현 내역, 마이그레이션 노트, 작업 기록 |
| 검증 | `docs/verification/` | 테스트 결과서, QA·e2e 결과 |
| 보고 | `docs/reports/` | 변경·완료 보고 (`/report` 의 문서 산출물) |
| 가이드 | `docs/guides/` | 사용자 설명서, 운영·설치 가이드, 화면 설명서 |

- 파일 이름은 `<YYYY-MM-DD>-<주제>.md`. 이미지가 딸리면 폴더로 —
  `<YYYY-MM-DD>-<주제>/index.md` + `shots/`
- 한 요청이 두 종류에 걸치면 **요청한 말**을 따른다 — "보고서" 면 `reports/`,
  "설명서" 면 `guides/`. 보고서 안의 신규 화면 설명서는 보고서에 둔다. 사용자가
  설명서를 따로 달라고 하면 그때 `guides/` 에 낸다
- **저장소에 이미 다른 체계가 있으면 그것을 따른다** (`docs/adr/`, `docs/spec/` 등).
  `CLAUDE.md` 의 `## 문서 자리` 절이 있으면 그것이 우선이다 (`/start` 가 남긴다)
- 이 표에서 빠지는 것:

| 무엇 | 자리 |
| --- | --- |
| 확인 증거 원본(스크린샷) | `tests/screenshots/` — 검증·보고 문서는 여기를 참조하거나 `shots/` 로 복사 |
| `CLAUDE.md` · `HANDOFF.md` | 저장소 루트 |
| 팀 명단 | `docs/team.md` (`/team` 이 흔적으로 읽는다. 옮기지 않는다) |
| 중간 산출물·임시 변환 | 스크래치패드. 저장소에 남기지 않는다 |

사용자가 경로를 지정했으면 그대로 쓴다. **경로를 보고에 적는다.**

## C. 영향 유형별 상세 — DB · 화면

A 의 3열 표는 "무엇이 달라졌나" 를 한 줄로 말한다. **스키마와 화면은 한 줄로 전달되지
않는다** — 컬럼 하나가 바뀌면 관계·기존 행·되돌리기가 따라오고, 화면은 글로 적으면
읽는 사람이 결국 띄워 본다. 영향 파일에 아래가 들었으면 해당 절을 **반드시** 붙인다.

### 무엇이 들었나 가른다

비교 기준(base)부터 정해 보고서 첫머리에 적는다 — 기본 브랜치와의 분기점
(`git merge-base`), 또는 사용자가 지정한 커밋.

```bash
git diff --stat <base>...HEAD      # 커밋된 변경
git status --short                 # 미커밋 변경
```

| 이런 파일이 바뀌었으면 | 붙일 절 |
| --- | --- |
| 마이그레이션, 스키마 정의, ORM 엔티티·모델, DDL(`*.sql`) | ERD 차이 |
| 기존 화면의 페이지·컴포넌트·스타일·문구 | 화면 전후 비교 |
| 새 라우트·새 페이지 | 신규 화면 설명서 |

스타일만 바꾼 컴포넌트라도 화면에 보이면 화면 전후 비교 대상이다. 판단이 애매하면 붙인다.

### 붙이는 방법 — 해당 절만 읽는다

| 붙일 절 | 읽을 문서 | 핵심 한 줄 |
| --- | --- | --- |
| ERD 차이 | [references/impact.md](references/impact.md#erd-차이) | 코드에서 읽는다. 변경 요약표 + 바뀐 테이블과 FK 로 닿는 테이블만 전후 두 장. 삭제·타입 축소·not null 추가는 기존 행 처리를 반드시 적는다 |
| 화면 전후 비교 | [references/impact.md](references/impact.md#화면-전후-비교) | 변경 전 캡처가 없으면 비교가 아니다. 같은 경로·데이터·창 크기. 못 찍으면 이유를 적고 그리지 않는다 |
| 신규 화면 설명서 | [references/impact.md](references/impact.md#신규-화면-설명서) | 처음 쓰는 사람이 이것만 보고 쓸 수 있게 — 목적·진입·권한·영역·입력·동작·상태. 실제로 찍은 것만 싣는다 |

해당하는 절이 없으면 이 문서를 읽지 않는다.

### 형식과 자리

- 이미지·다이어그램은 대화창에 보이지 않는다. **C 절이 하나라도 붙으면 문서 파일로
  만든다** — `$ARGUMENTS` 형식이 없으면 `md`. 대화창에는 A 뼈대와 파일 경로를 준다
- 자리: B.4 의 `docs/reports/<YYYY-MM-DD>-<주제>/` (`index.md` + `shots/`).
  확인 증거 원본은 `tests/screenshots/` 에 그대로 둔다
- **보고서의 절 제목에 번호를 붙이지 않는다.** 이 스킬 안의 순서·기호를 옮기지
  않는다 — 붙는 절만 들어가므로 번호가 빠지고 건너뛴다. 제목은 `## ERD 차이`,
  `## 화면 전후 비교 — 주문 목록` 처럼 내용으로 짓는다
- 만든 뒤 **열어 본다** — 이미지 경로 깨짐, 다이어그램 렌더 실패를 본다 (`/check`)
