# report — 매뉴얼 현행화 (기능 목록과 매뉴얼을 대조한다)

[SKILL.md B.5](../SKILL.md#5-매뉴얼-현행화--기능-목록과-매뉴얼을-대조한다) 에서 온다. "매뉴얼 최신화해줘",
"역할별 매뉴얼이 최신인지 확인하고 조치해줘", "가이드에 예시 화면이 없어" 를 받았을 때 이 순서로 한다.

## 왜

2026-10-05 ~ 11-12 사람이 쓴 메시지 9건(프로젝트 5개)이 매뉴얼 현행화였다 (`docs/analysis/2026-11-12-memory-prompt-review.md` 2.6).

> *"각 역할별로 매뉴얼이 잘 작성되어 있고, 최신상태인지 확인하여 조치해줘."* · *"가이드에 기능별 사용 예시 화면이 하나도 없어."*
> *"완료되면 …/admin/manual/admin, …/admin/manual/user 의 매뉴얼 정보 최신화 해줘."*

매뉴얼을 읽고 "잘 되어 있습니다" 라고 답하면 매뉴얼이 스스로를 근거로 삼는다. 빠진 기능은 매뉴얼에 없으니
매뉴얼만 읽어서는 보이지 않는다. **기준은 코드의 기능 목록이고, 매뉴얼은 대조 대상이다.**

## 1. 매뉴얼이 어디 있는지 찾는다

매뉴얼은 `docs/` 에만 있지 않다. 앱 안의 도움말 페이지가 정본인 경우가 많다.

| 어디 | 찾는 법 |
| --- | --- |
| 저장소 문서 | `docs/guides/` · `docs/manual*` · `README` 의 사용법 절 |
| 앱 안 페이지 | 라우트 정의에서 `manual` · `guide` · `help` · `도움말` · `매뉴얼` 을 grep. 본문이 마크다운 파일·DB 시드·컴포넌트 안 문자열 중 어디에 있는지까지 본다 |
| 사용자가 준 주소 | 그 주소의 라우트를 코드에서 찾아 본문 위치를 확정한다 |

역할별로 나뉘어 있으면(관리자·사용자) 각각이 한 단위다. 찾은 위치를 보고 첫머리에 적는다.

## 2. 기능 목록을 코드에서 뽑는다

라우트·메뉴 정의·권한(역할별 접근) 설정에서 뽑는다. 매뉴얼이나 기획서에서 뽑지 않는다.

- 메뉴에 노출되는 화면, 그 화면의 주요 동작(버튼·폼 제출·내보내기)
- 역할마다 보이는 메뉴가 다르면 역할별로 나눈다
- 숨김 처리·기능 플래그로 꺼진 것은 "꺼짐" 으로 표시하고 대조에서 뺀다

## 3. 대조표를 만든다

```
| 기능 (라우트) | 역할 | 매뉴얼 절 | 상태 | 무엇이 다른가 |
| --- | --- | --- | --- | --- |
| 주문 목록 (/orders) | 관리자 | 관리자 매뉴얼 3.1 | 낡음 | 매뉴얼은 엑셀 내보내기 버튼을 설명하지만 지금은 CSV 다 |
| 쿠폰 발급 (/coupons/new) | 관리자 | 없음 | 빠짐 | — |
| 포인트 적립 | 사용자 | 사용자 매뉴얼 5 | 매뉴얼에만 | 라우트가 2026-10 에 삭제됨 (`a1b2c3d`) |
| 로그인 (/login) | 공통 | 공통 1 | 맞음 | — |
```

상태는 넷이다 — `맞음` · `낡음`(문구·버튼·순서·화면이 다름) · `빠짐`(기능은 있는데 절이 없음) ·
`매뉴얼에만`(절은 있는데 기능이 없음). `낡음` 은 무엇이 다른지 한 줄로 적는다. 확인은 화면을 띄워 보거나 컴포넌트 코드를
읽어서 한다. 매뉴얼 문장만 보고 `맞음` 으로 두지 않는다.

## 4. 고친다

- 기존 매뉴얼의 **구조·문체·용어를 따른다** ([B.2](../SKILL.md#2-정본-문서를-갱신하는-요청은-새-문서가-아니다)). 새 절은 기능 순서에 맞는 자리에 끼운다
- `빠짐` 은 새 절을 쓴다. 쓰는 형식은 [신규 화면 설명서](impact.md#신규-화면-설명서)의 목적·진입·권한·입력·동작을 매뉴얼 문체로 옮긴 것이다
- `매뉴얼에만` 은 지운다. 기능이 꺼져 있을 뿐인지 불확실하면 지우지 말고 보고에 남긴다
- 앱 안 매뉴얼이면 본문이 있는 곳(마크다운·시드·컴포넌트)을 고치고, 화면에서 바뀐 것을 확인한다

## 5. 기능별 캡처를 넣는다

"예시 화면이 하나도 없어" 가 실제로 나온 요청이다. 절마다 그 기능 화면을 한 장 이상 넣는다.

- 실제로 띄워서 찍는다([up](../../up/SKILL.md#절차--띄운다-인자-없음)). 역할별 매뉴얼이면 그 역할로 로그인해서 찍는다
- 창 크기는 하나로 고정한다. 개인정보·실제 고객 데이터가 보이면 시험 데이터로 바꿔서 찍는다
- 자리는 매뉴얼이 이미 쓰는 이미지 폴더를 따른다. 없으면 매뉴얼 옆 `shots/` 에 둔다
- 못 찍은 절은 "캡처 없음 — <이유>" 로 보고에 남긴다. 그림을 그리거나 다른 화면 캡처로 대신하지 않는다
- 넣은 뒤 매뉴얼을 열어 이미지가 실제로 보이는지 본다 (`/check` 의 문서 산출물)

## 6. 보고

```
결론: 매뉴얼 2개 현행화 — 기능 24개 중 맞음 15 · 고침 5 · 추가 3 · 삭제 1, 캡처 22장 (2개 못 찍음)

매뉴얼 위치: 관리자 /admin/manual/admin (본문 content/manual/admin.md), 사용자 /admin/manual/user (content/manual/user.md)

| 기능 | 역할 | 이전 상태 | 한 일 | 캡처 |
(3의 대조표에 한 일·캡처 열을 더한 것)

남은 것: 정산 화면 캡처 — 시험 데이터에 정산 건이 없음
```

매뉴얼의 검색이나 목차 같은 **기능 요청**은 현행화가 아니다. 그런 요청이 같이 왔으면 따로 구현할 일로 나눠 적는다.

## 기능을 바꾼 작업의 끝에서

사용자가 "완료되면 매뉴얼도 최신화해줘" 처럼 말했으면, 그 작업에서 바뀐 라우트·화면만 골라 위 3~5 를 돈다. 전체 대조는 하지 않는다.
그런 말이 없었어도 바뀐 화면을 다루는 매뉴얼 절이 있으면 보고의 영향 파일에 "매뉴얼 영향: <절>" 로 적는다. 고칠지는 사용자가 정한다.
