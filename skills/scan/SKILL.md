# 지금 상태를 잰다

입력: `$ARGUMENTS` (비었으면 저장소 현황. `분석 <대상>` 이면 그 대상을 깊게 본다)

## 왜 이 명령이 있나

`현재 상태 확인해줘`(2회) · `완료 상태 확인해줘` · `현재 작업 목록 상태 확인` ·
`진행상황 알려줘` · `남은 작업 모두 정리해줘` · *"현재 상태를 분석해 문제점을 파악하고"*
— 상태를 묻는 지시가 2026-10-08 집계에서 7건 나왔다.

이 질문은 `/go` 와 다르다. `go` 는 상태를 복원한 뒤 **착수**한다. 상태만 묻는 사람에게
착수는 요청하지 않은 일이고, 그 사이 파일이 바뀌면 물은 상태가 사라진다.
그리고 `/tuzi` 는 명령을 고르는 지도라 상태를 깊게 재지 않는다.

**`/status` 가 아닌 이유** — Claude Code 내장 명령이 그 이름을 쓴다(버전·모델·계정
표시). 같은 이름이면 짧은 이름으로 불리지 않는다. `/help` 를 `tuzi` 로 바꾼 것과 같다.

## 두 규칙

1. **읽기만 한다.** 파일을 고치지 않고, 커밋하지 않고, 워커를 띄우지 않는다.
   에이전트 운영 질문도 하지 않는다 — 누가 고칠지가 걸리지 않는 일이다
2. **잰 값만 적는다.** 문서에 적힌 상태는 "문서가 말하는 것" 이지 상태가 아니다.
   모든 값에 근거(명령 결과·파일 경로·커밋)를 붙인다. 못 잰 것은 못 쟀다고 적는다

## 절차 — 현황 (인자 없음)

### 1. 문서가 말하는 상태

`HANDOFF.md` 의 "지금 당장 할 일"·"기다리는 것"·확인표, `CLAUDE.md` 의 게이트·운영,
`docs/` 의 로드맵·계획 문서의 진행 표기.

### 2. 실제 상태

| 무엇 | 보는 것 |
| --- | --- |
| 브랜치 | 현재 브랜치, 원격과 몇 커밋 앞/뒤인지, 기본 브랜치와의 거리 |
| 미커밋 | `git status --short` — 파일 수와 어느 영역인지 |
| 최근 단위 | `git log --oneline -10` — 마지막으로 끝낸 단위 |
| 열린 변경 요청 | 원격 저장소 도구가 있으면 열린 PR·상태. 없으면 "조회 수단 없음" |
| 작업 공간 | 워크트리 목록. 팀 운영이면 명단(`docs/team.md`)과 대조 — 명단 밖·병합 끝난·변경 남은 공간 |
| 워커 | 오케스트레이션 수단이 있으면 조회한 상태만 (`team` 규칙 3) |
| 게이트 | `CLAUDE.md` 의 게이트를 **한 번** 돌린다. 오래 걸리면(수 분) 돌리지 않고 마지막 기록을 인용하고 그렇게 적는다 |
| 실행 | 실행 중인 개발 서버·컨테이너가 있으면 응답 한 번. 띄우지는 않는다 |

### 3. 대조한다 — 이 명령의 핵심

문서와 실제가 어긋난 곳을 찾는다. **인계 문서는 자기 자신을 반영하지 못한다** —
"미커밋 둘을 커밋해야 한다" 가 이미 커밋돼 있고, "PR 열림" 이 이미 머지돼 있다.

| 흔한 어긋남 | 예 |
| --- | --- |
| 문서가 할 일로 적었는데 이미 끝났다 | 커밋·머지·배포가 된 상태 |
| 문서에 없는 변경이 있다 | 미커밋 파일, 문서 이후의 커밋 |
| 명단과 작업 공간이 다르다 | 명단 5개, 워크트리 16개 |
| 확인표의 "확인" 이 지금은 아니다 | 그때 초록이던 게이트가 지금 빨강 |

### 4. 남은 일과 다음 명령 하나

남은 일을 **할 일**과 **사용자 결정**으로 나눠 적는다(`handoff` 의 두 칸과 같다).
끝에 지금 부를 명령 하나를 이유 한 줄과 함께 권한다 — `/go`·`/check`·`/ship`·
`/team clean` 등. 권하기만 하고 부르지 않는다.

## 절차 — 분석 (`분석 <대상>`)

현황 1~3 을 한 뒤 대상을 깊게 본다.

| 대상 | 보는 것 |
| --- | --- |
| 기존 시스템·영역 | 진입점·모듈 경계·데이터 저장소. **만들어졌는데 호출되지 않는 것**(정의만 있고 호출부 없음, 테이블은 있는데 행 0) — `start` B3 와 같은 눈 |
| 요구사항 | 요구 문장마다 지금 어디까지 구현됐는지 — 코드 위치·테스트·화면으로. 구현 근거를 못 찾으면 "미구현 추정" 이 아니라 "근거 못 찾음" |
| 문제점 | 증상이 보이면 원인 후보를 적되, 고치지 않는다. 고칠 일이면 다음 명령으로 `/fix` 를 권한다 |

결과를 문서로 달라고 하면 `CLAUDE.md` 의 `## 문서 자리`, 없으면
[report 의 B.4](../report/SKILL.md#4-어디에-두나--프로젝트-docs-를-요청-종류로-나눈다) 의
`docs/analysis/<YYYY-MM-DD>-<주제>.md` 에 둔다. **이것이 이 명령이 쓰는 유일한 파일이다** —
요청받았을 때만.

## 하면 안 되는 것

- 상태를 보고 나서 "그럼 진행하겠습니다" 로 착수하는 것 — 부르는 것은 사용자다
- 문서에 적힌 상태를 재지 않고 옮겨 적는 것
- 조회하지 않고 워커·서버가 "돌고 있다" 고 쓰는 것
- 근거 칸을 비우는 것
- 대화 경과를 요약하는 것 — 묻는 것은 지금 상태다
