# 5. 내보낸다

입력: `$ARGUMENTS` (비었으면 `commit` — 로컬 커밋까지)

## 왜 이 단계가 있나

`커밋` 이 38건이고 `커밋 2 진행해`·`커밋 4 진행해`·`커밋하고 다음 단계 이어가` 처럼
**번호가 붙어 반복**됐다. 커밋은 이 사용자에게 **작업 단위 그 자체**다. 작업이 끝나면
커밋이 따라오는 것이 기본값이고, 묻고 기다릴 일이 아니다.

반대로 **바깥으로 나가는 것**(push·PR·merge·배포)은 `master` push 가 곧 운영 배포인
저장소가 있어 사람 확인을 받는다.

## 범위 — 어디까지 묻지 않는가

| 인자 | 하는 일 | 묻나 |
| --- | --- | --- |
| `commit` (기본) | 게이트 → 브랜치 → add → 로컬 커밋 | 묻지 않는다 |
| `push` | 위 + 원격 push | **사용자가 이 턴에 말했으면** 묻지 않는다 |
| `pr` | 위 + PR 생성 | 〃 |
| `merge` | 위 + PR 을 기본 브랜치로 병합. push·PR 이 이미 있으면 그 PR 을 병합한다 | 〃. 병합 대상이 운영 배포 브랜치면 한 번 더 확인 |
| `deploy` | 배포 명령 실행 + 공개 주소 확인 | 〃 |

`"커밋해줘"` 에 push 를 끼워 넣지 않는다. 인자가 없으면 로컬 커밋에서 멈춘다.
인자는 사슬이다 — 뒤의 것이 앞의 것을 포함한다. `/ship merge` 하나로 커밋·push·PR·병합까지 간다.
`/ship pr merge` 처럼 함께 적어도 같다.

## 절차

### 1. 게이트를 한 줄로 돌린다

프로젝트의 **묶음 게이트 스크립트**를 쓴다(`CLAUDE.md` 에 적혀 있으면 그것).
없으면 매니페스트 스크립트에서 가장 포괄적인 것을 찾고, 그래도 없으면 있는 검사를
`&&` 로 엮어 돌린다. 손으로 고르면 하나를 빠뜨린다.

> 실례 — `typecheck && lint && test` 셋만 돌리고 커밋해 문서 둘이 서식 위반인 채로
> 들어갔다. lint 는 서식 검사기를 보지 않는다.

`/start` 에서 재 둔 **기준선**보다 나빠졌으면 커밋하지 않는다. 기준선부터 빨갛던
것은 보고에 "원래 빨강" 으로 적고 진행한다.

### 2. 브랜치를 확인한다

보호 브랜치(`main`·`master`·`develop`·`dev`)에 있으면 **feature 로 분기한 뒤** 커밋한다.

### 3. 경로를 명시해 add 한다 — `git add -A` 금지

> 무슨 일이 일어나나 — 검증 에이전트가 소스를 고쳤다 되돌리는 방식으로 돌 때,
> 그 사이 `git add -A` 로 커밋하면 **돌연변이 중간 상태가 커밋에 박제된다.**
> 에이전트가 나중에 되돌리면 작업 트리는 멀쩡하고 결함은 히스토리에만 남는다. 실제로 났다.

### 4. 커밋한 뒤 들어간 것을 본다

```bash
git show --stat --oneline HEAD
```

**의도한 파일만 들었는지** 본다. 섞였으면 작업 트리를 건드리지 말고 색인만 되돌려 amend.

```bash
git restore --source=HEAD~1 --staged <경로>
git commit --amend --no-edit
```

`git checkout <커밋> -- <경로>` 는 작업 트리까지 덮어써 다른 작업과 경합한다.

결정 이력 파일이 바뀌었으면 함께 넣는다. 이 커밋이 어떤 결정을 반영했으면 그 항목의 결과에
커밋·PR 을 잇고 상태를 `반영됨` 으로 올린다 ([결정 이력](../go/references/decisions.md)).
해시는 그 커밋 안에 적을 수 없다 — 해시를 적으려고 커밋을 하나 더 만들지 말고 결과에 커밋 제목을
적는다. 해시와 PR 번호는 다음에 이 파일을 고칠 때 잇는다.

### 5. 바깥으로 내보낸다 (인자가 있을 때만)

- **push** — 현재 feature 브랜치만. 보호 브랜치로 직접 push 하지 않는다. force push 는 따로 묻는다
- **pr** — 본문은 `/report` 형식(3열 표 + 확인한 것/안 한 것)
- **merge / deploy** — 끝나면 **공개 주소에 요청을 보내 응답 코드를 본다**
  (`/check` 의 배포 기준). 확인하지 못했으면 못 했다고 적는다

## 커밋 메시지

저장소의 기존 문체를 따른다. 대화형 보고의 존댓말을 옮기지 않는다.

- 제목은 **무엇이 달라졌나** 한 줄. 유형 접두(`fix:`)는 저장소 관례가 있을 때만
- 본문은 **왜**와 **어디에 번지나**. 표 하나와 핵심 문단이면 충분하다
- 게이트 결과를 짧게 적는다
- 적은 내용이 파일에 실제로 있는지 `grep` 으로 대조한 뒤 적는다

## "이번만" 과 "앞으로" 를 구분한다

`이번만 push 해줘` 는 1회 허가고, `앞으로는 묻지 말고 push 해` 는 정책 변경이다.
후자면 기록으로 남긴다(메모리·설정). 전자를 정책으로 확장하지 않는다.
