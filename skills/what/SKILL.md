# 결정을 풀어 준다

입력: `$ARGUMENTS` (비었으면 직전 응답이 물은 결정. 번호·문장 일부가 있으면 그 결정)

## 왜 이 명령이 있나

AI 가 결정을 청했는데 사용자가 무엇을 정하라는 건지 몰라 되물은 메시지가 집계에 나온다.

> *"뭘 결정해야 하는데?"* · *"남은 결정이 뭐야?"* · *"D-1 결정이 뭐야?"* (tuzi-oa, 10-22)
> *"어떤 결정을 해야 하는거지?"* (ams, 10-17) · *"format-audit .xlsx 뭘 어떻게 결정하라는거야?"* (tuzi-oa, 11-12)

넓게 세면 묻는 문장을 알아듣지 못한 메시지가 약 26건·프로젝트 6개다
(`docs/analysis/2026-11-12-memory-prompt-review.md` 2.1).

[묻는 형식](../go/references/asking.md)은 **묻는 쪽**의 규칙이다. 그래도 바이브코딩 중에는 이런 질문이 온다 —
형식을 지키지 않은 질문, 다른 세션이 남긴 결정, 화면 밖으로 밀려난 질문. 그때 사용자가 같은 말을 길게 다시 쓰지 않고
부를 수 있는 것이 이 명령이다. 이름은 처음에 `decide` 였다가 *"skill 명 어려우니까 /what 으로 해줘"*(2026-11-16)로 바꿨다 — 되물을 때 떠오르는 말("뭘?")에 가깝다. 되물을 때 사용자가 원하는 것은 대개 네 가지다 — **무엇을**, **왜 내가**,
**고르면 뭐가 달라지나**, **안 고르면 어떻게 되나**.

## 두 규칙

1. **풀어 쓰기만 한다.** 파일을 고치지 않고 결정을 대신 내려 착수하지 않는다. 답은 사용자가 다음 말로 준다
2. **원래 질문을 바꾸지 않는다.** 선택지를 새로 만들거나 빼지 않는다. 다시 보니 권고가 달라졌거나 선택지가 틀렸으면
   숨기지 말고 "처음 물을 때와 달라진 점" 으로 적는다

## 절차

### 1. 기다리는 결정을 찾는다

`$ARGUMENTS` 가 있으면 그것을 찾는다. 없으면 이 순서로 보고, 앞에서 나오면 뒤는 건너뛴다.

| 순서 | 어디 | 무엇 |
| --- | --- | --- |
| 0 | 같은 세션의 직전 응답들 | 끝에 묻거나 "정해 주세요" 한 것. 화면 위로 밀려난 질문까지 |
| 1 | `HANDOFF.md` 「기다리는 것」 | 지난 세션이 남긴 사용자 결정 |
| 2 | [결정 이력](../go/references/decisions.md) 의 상태 `대기` | 묻고 답을 못 받은 결정 |
| 3 | `docs/design/` 등 설계서의 결정 목록 | `spec` 이 남긴 미정 항목 |

번호(D-1, N-12, 6-D)를 받았으면 그 번호가 적힌 문서를 찾아 내용으로 바꾼다. **찾지 못하면 찾지 못했다고 쓴다** —
번호에서 내용을 짐작하지 않는다.

여럿이면 서로 걸린 것끼리 묶고, 앞의 것이 정해져야 뒤의 것을 물을 수 있는 순서로 늘어놓는다.

### 2. 사용자가 정할 일인지 가른다

결정을 청한 것 중에는 사용자 몫이 아닌 것이 섞여 있다. [go 의 자율 범위](../go/SKILL.md#자율-범위--어디까지-묻지-않는가)
기준으로 가른다.

| 가름 | 기준 | 어떻게 쓰나 |
| --- | --- | --- |
| 사용자 결정 | 워크트리 밖으로 번진다(push·배포·운영 DB·외부 전송·비용), 되돌리기 어렵다, 취향·사업 판단이다 | 3단계 형식으로 푼다 |
| AI 가 정해도 되는 것 | 워크트리 안이고 되돌리기 쉽고 관례가 있다(폴더 이름, 라이브러리 버전, 내부 함수 구조) | "이건 정하지 않으셔도 됩니다 — 권고대로 하겠습니다" 와 권고 한 줄 |
| 이미 정한 것 | 결정 이력·`CLAUDE.md`·이 대화에 답이 있다 ([제안의 범위](../go/references/proposing.md) 규칙 1) | "<날짜>에 <답>으로 정하셨습니다" 와 근거 위치 |

### 3. 하나씩 풀어 쓴다

```
**<무엇을 정하나 — 번호 없이 읽히는 한 문장>** (원래 이름: <문서의 번호·용어가 있으면>)
- 지금 상태: <이 결정이 걸린 것이 지금 어떤지 — 잰 사실 한두 줄>
- 왜 사용자가: <AI 가 정하지 않는 이유 한 줄 — 비용·되돌리기·바깥·취향>
- (a) <선택지> → <사용자가 보거나 겪는 결과 · 되돌릴 수 있나>
- (b) <선택지> → <〃>
- 안 정하면: <무엇이 멈추고 무엇은 계속 되나>
- 권고: (a) — <이유 한 줄>
```

- 결과는 **사용자 쪽 말**로 쓴다 — 화면에 무엇이 보이나, 데이터가 어떻게 되나, 돈·시간이 얼마 드나, 되돌릴 수 있나.
  구현 내부의 이름(`ImageToken 재설계`)으로 쓰지 않는다
- 처음 나오는 전문어는 한 마디로 풀거나 쓰지 않는다. 풀 말이 길면 `용어:` 한 줄을 그 결정 아래에 둔다
- "지금 상태" 는 파일·명령으로 확인한 것만 쓴다. 확인하지 못했으면 "확인 못 함" 으로 쓴다
- 서로 걸린 결정은 앞의 것 하나만 이 형식으로 쓰고, 뒤의 것은 `이 답에 따라 다음에 물을 것: <한 문장>` 한 줄로 둔다

### 4. 답하는 법을 한 줄로 알린다

끝에 `"권고대로" 또는 "(b)" 처럼 말로 답하시면 됩니다` 를 붙인다. 번호로 답하라고 하지 않는다.
사용자가 답하면 그 답을 [결정 이력](../go/references/decisions.md)에 남기고 원래 하던 일로 돌아간다 — 그때부터는 `go` 의 규칙이다.

## 보고

```
기다리는 결정 2개 — 하나만 정하시면 나머지는 따라옵니다.

**공유 파일을 여는 열쇠를 서버에도 둘까요?** (원래 이름: 설계서 D-1)
- 지금 상태: 공유 대화상자 화면이 이 답을 기다리며 멈춰 있습니다. 나머지 화면은 끝났습니다
- 왜 사용자가: 서버 관리자가 파일을 열 수 있게 되는지가 달라집니다 — 보안 정책의 문제입니다
- (a) 서버에도 둔다 → 여러 사람이 같은 파일을 동시에 편집할 수 있습니다. 서버 관리자도 열 수 있습니다. 나중에 (b)로 바꾸려면 기존 파일을 다시 암호화해야 합니다
- (b) 기기에만 둔다 → 서버 관리자도 못 엽니다. 동시 편집이 안 되고, 기기를 잃으면 복구 코드가 있어야 합니다
- 안 정하면: 공유 기능만 멈추고 나머지 작업은 계속합니다
- 권고: (a) — 설계서가 동시 편집을 필수로 적었습니다
이 답에 따라 다음에 물을 것: 복구 코드를 언제 드릴지

정하지 않으셔도 되는 것: 업로드 폴더 이름 — `uploads/` 로 하겠습니다 (관례, 바꾸기 쉬움)

"권고대로" 또는 "(b)" 처럼 말로 답하시면 됩니다.
```

## 하면 안 되는 것

- 결정을 대신 내리고 착수하는 것 — 2단계에서 "정하지 않으셔도 됩니다" 로 가른 것도 실행은 답을 받은 뒤다
- 번호를 다른 번호로 바꿔 설명하는 것 (`D-1 은 R-3 의 하위 결정입니다`)
- 원래 질문에 없던 선택지를 슬쩍 더하거나 권고를 말없이 바꾸는 것
- 문서를 못 찾았는데 번호에서 내용을 짐작해 쓰는 것
- 사용자가 이미 정한 것을 결정 대기로 다시 올리는 것
- 결정과 상관없는 진행 경과를 길게 요약하는 것
