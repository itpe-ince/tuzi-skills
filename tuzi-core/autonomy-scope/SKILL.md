# 어디까지 묻지 않고 하는가

## 왜 이 스킬이 있나

사용자가 명시했다 — *"워크스페이스 내에 있는 파일 처리 및 명령어 수행은 사람에게
확인 받지 말고 알아서 처리하라"*, *"워크트리 내에서 파일 삭제, 도커 생성 및 삭제 등은
에이전트가 알아서 처리 했으면 좋겠어"*. 앞서 *"프리앰블로 들어온 지시는 되묻지 말고
바로 착수하라"* 도 받았다.

확인 요청이 흐름을 끊고 있었다. **같은 지시가 두 번 나왔다는 것은 기본 동작이
틀어져 있다는 뜻이다.**

## 경계 — 이 한 장이 전부다

판단 기준은 **되돌리기 쉬운가**가 아니라 **워크트리 밖으로 번지는가**다.

### 묻지 않는다 (워크트리·워크스페이스 내부)

- 파일·디렉터리 삭제, 덮어쓰기, 이동
- 도커 컨테이너·이미지·볼륨·네트워크 **생성 및 삭제**, 컴포즈 up/down
- 프로세스 종료 (개발 서버·워커)
- 패키지 제거 (`npm`/`pnpm`/`yarn`/`pip` 의 remove·uninstall)
- 셸 명령 수행, 스크립트 작성·실행
- 로컬 커밋, 브랜치 생성

**하고 나서 무엇을 했는지 보고에 적는다.** 묻지 않는 대가가 보고다.

### 묻는다 (워크트리 밖으로 번진다)

| 무엇 | 왜 |
| --- | --- |
| 원격 push · PR · merge | `master` push 가 운영 배포인 저장소가 있다 |
| 운영 DB 의 모든 DDL·DML | 되돌릴 수 없다. 운영 DB 를 날린 기록이 있다 |
| 머신 전역 정리 (`docker system prune`·`image prune`) | 다른 프로젝트의 이미지·볼륨까지 지운다 |
| 전역 패키지 관리자 (`brew uninstall` 등) | 워크트리와 무관한 머신 상태다 |
| 권한·설정 자체를 바꾸는 것 (`~/.claude/settings.json`) | 이후 모든 판단의 전제를 바꾼다 |
| 외부 서비스로 내보내기 (메일·메시지·웹훅 등록·배포) | 캐시·색인에 남아 삭제해도 회수되지 않는다 |
| 원격 서버의 공용 자원 | 같은 호스트에 다른 서비스가 돈다 |
| 비밀번호·키 교체, 접속 방식 변경 | 잠금 위험이 있다 |
| 저수준 쓰기 (`dd` 등) | 장치를 건드릴 수 있다 |

### 경계에 걸리면

**워크트리 안의 일 전부를 먼저 끝내고**, 바깥 작업만 모아 한 번에 묻는다.
작업을 세워 두고 묻지 않는다.

## 질문하는 법

묻기로 정했으면 질문을 **하나로** 모은다.

- 선택지 네 개를 늘어놓지 않는다. 권고를 먼저 쓰고 사유 한 줄을 붙인다
- 답에 의존하지 않는 일은 묻기 전에 끝내 놓는다
- 오케스트레이션 맥락이면 사용자에게 직접 묻는 대신 그 채널의 질의 경로를 쓴다

## 되돌릴 수 없는 작업을 할 때

묻지 않는 범위라도 **백업은 남긴다.** 무료다.

- 설정 파일을 고치기 전 `cp` 로 타임스탬프 백업
- 많은 파일을 지우기 전 지울 목록을 먼저 출력해 세어 본다
- 추적 파일을 지웠으면 보고에 **git 영향**을 적는다 (미커밋 삭제가 남는다)

## 거부 반복의 처리

같은 요청을 사용자가 **재확인**했으면 그것은 결정이다. 우려를 한 문장으로 전하고
**전체 요청을 수행한다.** 같은 우려를 두 번 말하지 않는다.
