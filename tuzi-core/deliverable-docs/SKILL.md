# 문서 산출물을 만든다

## 왜 이 스킬이 있나

`만들` 이 100건(7.3%), `문서` 가 27건이다. `docs/…-설치결과서.md 워드 문서로
만들어줘`, `docs/architecture.md 에 두 기획 반영해줘`, `로드맵 재편해줘` 처럼
**새로 만드는 요청과 정본을 갱신하는 요청이 섞여** 반복된다.

## 1. 폰트 — Pretendard

보고서·완료 결과물로 **문서 파일을 생성할 때 본문 폰트는 Pretendard 로 지정한다.**
대상: `html` · `pptx` · `docx` · `xlsx` · `pdf`. 코드 블록·터미널 출력은 예외로
기존 모노스페이스를 쓴다(Pretendard 는 모노스페이스가 아니다).

> 무슨 일이 일어나나 — 산출물마다 폰트가 제각각이라 같은 프로젝트의 리포트인데
> PPT 는 맑은 고딕, HTML 은 시스템 기본, PDF 는 굴림으로 나온다. 한글 자간·굵기가
> 달라 문서를 이어 붙이면 티가 난다.

### 폴백 스택

Pretendard 가 없는 환경에서도 한글이 깨지지 않게 **항상 폴백을 함께 지정한다.**

```
Pretendard, "Pretendard Variable", -apple-system, BlinkMacSystemFont,
"Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif
```

### 포맷별 지정 방법

| 포맷 | 어떻게 넣나 |
| --- | --- |
| HTML | CDN 웹폰트를 `<link>` 로 불러오고 `body { font-family: … }` 에 위 스택을 넣는다 |
| pptx | 텍스트 런마다 폰트 이름을 지정하고, **한글은 East Asian(`a:ea`) 속성까지** 같이 지정해야 실제로 적용된다 |
| docx | 스타일 폰트 + **`w:eastAsia` 속성**을 함께 설정 |
| xlsx | 셀/스타일에 폰트 이름 적용 |
| pdf | HTML→PDF 면 위 HTML 규칙을 그대로 태운다. 직접 생성이면 TTF 를 폰트로 등록해 임베드한다 |

CDN: `https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css`

### 적용됐다고 단정하지 않는다

머신에 Pretendard 가 설치돼 있지 않으면 pptx·docx·xlsx 는 **폰트 이름만 박히고
로컬 미리보기는 폴백으로 렌더된다.** 화면으로 폰트를 검증해야 하는 작업이면
설치 여부를 먼저 확인하고, 없으면 **그 사실을 보고에 적는다.**

```bash
# macOS 설치 확인
ls ~/Library/Fonts /Library/Fonts 2>/dev/null | grep -i pretendard
```

사용자가 특정 폰트를 명시하면 그 지시가 이 규약보다 우선한다.

## 2. 정본 문서를 갱신하는 요청

`docs/X.md 에 반영해줘`·`로드맵 재편해줘` 는 **새 문서를 만드는 일이 아니다.**

- 기존 문서의 **구조와 문체를 따른다.** 새 절을 끼워 넣을 자리를 먼저 찾는다
- 그 문서가 스펙 오라클이면, 요청이 문서와 **어긋날 수 있는지** 먼저 본다.
  모순이면 코드를 고치기 전에 그 모순을 사람에게 알린다
- 문서를 고쳤으면 **`grep` 으로 결과를 확인**한다. 특히 새 ID·새 행을 넣었을 때
  (`change-report` 스킬 규칙 4)
- 문서가 코드와 어긋난 채 남은 곳을 발견하면 보고에 적는다. 조용히 고치지 않는다

> 실례 — 프리뷰 URL 을 경로 기반으로 바꾼 커밋이 들어간 뒤에도 `.env.example` 의
> 주석은 와일드카드 도메인 방식을 설명하고 있었다. 문서가 뒤처진 것을 아무도 모른다.

## 3. 변환 요청

`.md` → 워드·PDF 로 바꿔 달라는 요청이 반복된다.

- **원본 마크다운을 그대로 옮기지 않는다.** 제목 단계·표·코드 블록이 그 포맷에서
  어떻게 보이는지 보고 맞춘다
- 표가 페이지를 넘기면 쪼갠다. 코드 블록은 모노스페이스를 유지한다
- 산출물 경로를 보고에 적는다. 만든 뒤 **열어 본다** (`verify-for-real` 스킬)

## 4. 어디에 두나

| 요청 | 자리 |
| --- | --- |
| 저장소의 정본 문서 | `docs/` 아래 기존 체계 |
| 확인 증거(스크린샷·결과서) | 테스트 폴더 (`tests/screenshots/` 등) |
| 중간 산출물·임시 변환 | 스크래치패드. 저장소에 남기지 않는다 |

사용자가 경로를 지정했으면 그대로 쓴다. 지정하지 않았으면 위 표에 따라 정하고
**경로를 보고에 적는다.**
