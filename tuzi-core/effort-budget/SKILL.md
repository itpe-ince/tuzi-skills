# 검증에 상한을 둔다

## 왜 이 스킬이 있나

사용자가 **토큰 소비와 반복을 직접 지적**했다. "진행하다 되돌리고 무한 반복하는 것처럼
보인다", "최대 토큰량에서 70% 내외일 때 세션을 넘겨야 하지 않나", "나머지 빨리 끝내줘".

한 저장소에서 작업 하나(스키마+모델+변환기)에 **커밋 20개**를 썼다. 전체 119 커밋 중
**38개(32%)가 보강·검증·정정**이었다. 어떤 커밋은 검증을 **5라운드** 돌았고, 4·5라운드가
찾은 것은 *"테스트가 테스트를 제대로 검사하는지"* 였다 — 제품 동작과 무관한 층이다.

**그 2주 동안 제품은 한 번도 돌지 않았다.** 그 저장소가 문서에 열네 번 적은 실패
모양이 "만든 것과 쓰는 것이 끊긴 것" 인데, **작업 방식 자체가 그 모양이었다.**

## 규칙

### 1. 검증은 1라운드

- 보안·데이터 손실만 **차단**으로 받는다. 나머지는 **기록만** 한다
- "테스트를 검사하는 테스트" 는 차단이 아니다
- 2라운드를 돌리기 전에 묻는다 — **"이게 제품을 돌게 하는가?"** 아니면 기록한다
- 검증 에이전트는 비싸다(라운드당 10만~18만 토큰). 부르기 전에 같은 질문을 한다

### 2. 완료 기준은 끝에서 끝까지 1회 성공이다

단위 테스트 통과는 완료가 아니다 (`verify-for-real` 스킬). 반대로, **끝에서 끝까지
한 번 성공했으면 더 깎지 않는다.** 남은 것은 기록으로 넘긴다.

### 3. 범위를 좁혀 돌린다

- 테스트·돌연변이는 **해당 파일·패키지로 좁혀** 돌린다
- 전체 스위트는 **커밋 직전 한 번만**. 포기하지 않는 이유 — "단독이면 통과하고
  전체면 깨지는" 스펙이 실제로 있었다
- 출력은 필요한 줄만 뽑는다(`Tests N passed` 한 줄). 전체 로그를 받지 않는다
- 중간 확인용 `grep`·`sed` 출력도 필요한 줄만 자른다

### 4. 되돌린 뒤 되돌려졌는지 확인한다

> 무슨 일이 일어나나 — 복원 치환이 **조용히 0건 치환**하고 스크립트는 성공으로
> 끝났다. 그 상태로 다음 검사를 돌려 "초록"을 받았고, 하마터면 그것을 "가드가
> 변별력 없다"는 근거로 보고할 뻔했다. **두 번** 났다.

- 백업은 `cp`. **복원도 `cp`** (치환 금지)
- 복원 직후 기준 실행을 한 번 더 해 **원래 건수와 같은지** 본다. 다르면 복원이 안 된 것
- 한 번에 **하나만** 건다
- **위험은 깨뜨리는 쪽이 아니라 되돌리는 쪽에 있다**

### 5. 일괄 치환 스크립트는 매번 저장한다

> 무슨 일이 일어나나 — `write` 를 맨 끝에 한 번만 두면, 중간 `assert` 가 죽는 순간
> **그 전에 성공한 치환도 전부 사라진다.** 파일은 그대로인데 성공 로그(`✓`)는 이미
> 출력돼 있어 일부는 됐다고 착각한다.

치환마다 저장한다. 또는 전부 성공했을 때만 쓰되 **로그도 끝에 한 번에** 낸다 —
로그와 파일이 같이 움직여야 한다.

### 6. 컨텍스트가 차기 전에 인계한다

사용자가 **70% 내외**를 임계로 제시했다. 그 선에 닿으면 새 작업을 시작하지 말고
인계 문서를 쓴다. 인계 문서에 넣을 것:

| 항목 | 왜 |
| --- | --- |
| 한 줄 현황 | 무엇이 되고 무엇이 안 되나 |
| 지금 당장 할 일 | 다음 세션의 첫 한 수 |
| 확인한 것 / 확인 안 한 것 | 통과로 착각하지 않게 |
| 하면 안 되는 것 | 되돌릴 수 없는 사고 목록 |
| 자주 쓰는 명령 | 복구 비용 절감 |

**인계 문서는 자기 자신을 반영하지 못한다** — 쓰는 시점에 미커밋인 항목이 커밋 뒤
해결된 상태로 발견된다. 읽는 쪽이 `git status` 로 대조해야 한다 (`resume-work` 스킬).

## 하면 안 되는 것

- 돌연변이마다 전체 스위트를 돌리는 것
- 같은 파일을 3회 이상 왕복하며 다듬는 것 — 멈추고 기록한다
- 커밋 메시지를 길게 쓰는 것. 표 하나와 핵심 문단이면 충분하다
- 사용자가 "빨리"·"그만" 이라고 한 뒤에도 검증 라운드를 추가하는 것
