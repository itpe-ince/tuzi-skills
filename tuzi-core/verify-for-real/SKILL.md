# 돌려 보지 않은 것을 됐다고 적지 않는다

## 왜 이 스킬이 있나

`확인` 이 사람이 쓴 메시지의 **11.0%(150건)** 로 지시 동사 중 1위다. `띄워` 40건, `스크린샷`·`캡처`
13건이 뒤를 받친다. `다시 확인해봐` 가 반복됐다 — **이미 한 보고를 사용자가 믿지
못했다는 기록이다.**

구현 동사(`구현` 1.2%, `설계` 1.2%)보다 아홉 배 많다. 만드는 일이 아니라 **만든
것이 진짜 되는지**가 반복 요청의 본체다.

## 완료 기준

> **완료는 끝에서 끝까지 1회 성공이다. 단위 테스트가 아니다.**

단위 테스트 1,200건이 초록인 채로 제품이 2주간 한 번도 돌지 않은 사례가 있다
(devx-collabo, 2026-09~10: DB 의 `Task` 가 0건). 테스트는 **내가 쓴 것이 내 생각대로
도는지**를 보고, 제품이 도는지는 보지 않는다.

## 절차

### 1. 무엇을 확인할 수 있는지 먼저 센다

| 변경 성격 | 최소 확인 |
| --- | --- |
| 순수 함수·스키마 | 단위 테스트 + 실제 입력 한 건 |
| API·잡·워커 | 실제로 요청/작업을 넣어 상태 전이를 DB·로그에서 본다 |
| UI | **띄워서 눈으로 본다.** 스크린샷을 남긴다 |
| 배포·인프라 | 공개 주소에 요청을 보내 응답 코드를 본다 |
| 설정 변경 | **그 설정을 쓰는 그 컨테이너 안에서** 호출해 본다 |

### 2. 설정은 "실제 경로에서" 확인한다

목록 API·문서를 근거로 단정하지 않는다. 같은 대상을 부르는 이름 체계가 둘일 수 있다.

> 실례 셋 — ① 호스트 경로로 바꿨더니 워커가 다른 망이라 타임아웃(단독 `docker run`
> 으로만 확인했다). ② 목록 API 의 이름으로 "고쳤더니" 게이트웨이는 별칭을 받아 403
> (멀쩡한 설정을 망가뜨렸다). ③ 키를 골라 옮기며 하나를 빠뜨려 egress 가 막혔다.
> **셋 다 "확인했다"고 생각한 상태에서 났다.**

### 3. 증거를 파일로 남긴다

`캡처를 저장소(tests/screenshots/)에 남겨줘` 가 반복됐다. 확인은 휘발되므로 남긴다.

- 스크린샷 → 저장소의 테스트 폴더. 경로를 보고에 적는다
- 로그·쿼리 결과 → 결과 문장을 보고에 인용한다. 통째로 붙이지 않는다
- **화면을 만들었으면 캡처해서 직접 열어 본다.** 안 보고 넘기면 비어 있거나 잘못
  그려진 화면을 그대로 넘기게 된다

### 4. 도구가 없으면 **설치하지 말고 스킵한다**

e2e 도구(브라우저 자동화 등)가 프로젝트에 없으면 임의로 설치하지 않는다. 통과한
작업을 도구 설치 실패로 실패로 만들지 않는다. **스킵했다고 보고에 적는다.**

## 보고 규칙 — 확인한 것과 안 한 것을 나눈다

보고에 **두 칸**을 만든다.

```
### 확인한 것
| 무엇 | 증거 |
| 로그인 왕복 | 브라우저에서 눌러 세션 쿠키 발급 확인, tests/screenshots/login.png |

### 확인하지 않은 것 — 여기부터 의심한다
- 웹훅 등록: 레포에 훅이 없다. PUBLIC_URL 이 localhost 이던 시절의 제약이 남았다
```

**확인하지 못한 것을 통과로 기록하지 않는다.** 이것이 이 스킬의 단 하나의 금지다.
"아마 될 것이다"는 확인이 아니다. 추론으로 그린 선은 추론이라고 말한다.

## 하면 안 되는 것

- 단위 테스트 초록을 완료로 보고하는 것
- "정상 동작합니다" 를 실행 없이 쓰는 것
- 확인 못 한 항목을 보고에서 빼는 것 — 빠지면 사용자가 된 줄 안다
- UI 를 만들고 화면을 안 보는 것
